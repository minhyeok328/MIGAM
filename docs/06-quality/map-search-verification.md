# 지도 검색 검증

## 범위와 원인

현재 노출되는 17개 전시·9개 기관을 대상으로 한다. 정본 기관 표시명에 포함된 `본관 전시공간`, `행궁 본관`이 카카오 장소명과 달라 세종·수원에서 0건이 발생했다. 다른 기관에서도 부속 시설·다른 동이 함께 반환된다. 기관·지역·실제 venue에 묶은 검토된 장소명과 주소를 사용하며 API·DB 정본은 변경하지 않는다. 현재 목록 밖의 전시장까지 같은 주소라고 추론하지 않는다.

주소 검색은 [Kakao Geocoder 공식 계약](https://apis.map.kakao.com/web/documentation/#services_Geocoder_addressSearch)에 따라 EXACT 매칭을 사용한다. 지도의 주소 좌표는 현관·실내 전시실을 보장하지 않는다. 최신 사용자 요청에 따라 검토된 장소명·공식 주소와 일치하는 후보는 자동 표시한다. 미검토 후보는 사용자 선택을 요구한다. 지도 주변 안내·링크는 제거했으며 후속 요청에 따라 지도 안에 내 위치·확대·축소·전시장 복귀 버튼을 제공한다. 위치 권한은 내 위치 버튼을 직접 누를 때만 요청한다.

2026-09-17 기존 DB의 읽기 전용 API와 Vite 5173에서 다음 대표 전시를 각각 열어 명시적 검색 → 일치 후보 선택 → Kakao 지도 표시를 확인했다. 내 위치 권한은 요청하지 않았다.

실제 Geocoder도 임시 로컬 검증 페이지에서 9개 공식 주소를 각각 EXACT 검색하여 일치하는 도로명 주소가 반환됨을 확인했다. 세종은 `세종대로 지하 175`도 반환되어, EXACT 옵션 외에 응답 주소 대조가 필요함을 확인했다. 검증 페이지는 삭제했다. 이는 API 연결 확인이며 실제 9개 전시 화면에서는 이름 검색으로 성공했다. 이름 실패 → 주소 fallback UI는 키 없는 컴포넌트 테스트로 검증했다.

검색 API가 반환한 현재 17개 전시의 기관·지역·venue를 검색 계획과 대조하여 누락 0건을 확인했다. 사진미술관의 데스크톱 지도와 국립민속박물관의 390px 화면에서 주소·링크 줄바꿈·후보 선택·지도 표시를 확인했다.

`npm run test -- src/features/map src/app/Product.test.tsx` 32개와 `npm run build`가 통과했다. 검사는 9개 기관의 검색 계획, 다른 venue·지역의 매핑 차단, 부속 시설·다른 주소 배제, 명시적 실행·선택, API 오류 때 호출 중지, 주소 fallback 구분, 재검색 시 이전 지도 정리, 키 없는 실행·데모 경계, 실제 SDK 계약을 모사한 주소 응답 검증을 포함한다. 미래 기관의 장소명·주소는 검토 등록이 필요하며 이 결과를 미등록 기관까지의 보장으로 확대하지 않는다.

## 상세 진입 시 자동 지도 표시 검증 (2026-09-17)

사용자는 상세 화면에서 장소 찾기·후보 선택 없이 지도를 바로 보도록 요청했다. 검토된 이름·주소 필터와 제한된 재검색은 유지하며 상세 진입 시 자동 실행한다. 같은 주소의 여러 적합한 후보는 검토된 대표 장소명을 우선 표시한다. 실패·0건일 때만 `지도 다시 불러오기` 버튼을 제공한다.

위 9개 대표 전시를 각각 새로 열어 아무 지도 버튼도 누르지 않은 상태에서 올바른 지도 영역과 Kakao 지도가 나타나고 `지도에서 장소 찾기` 버튼이 없는 것을 확인했다. 세종 지도는 실제 타일·마커까지 화면으로 확인했다. 현재 위치 권한은 요청하지 않았다.

`npm run test -- src/features/map src/app/Product.test.tsx` 33개와 `npm run typecheck`가 통과했다. 자동 표시 관련 검사는 StrictMode 중복 검색 방지, 대표 장소 우선, 공식 주소 fallback 자동 표시, 미검토 후보의 선택 요구, SDK 실패·0건·지도 렌더링 실패의 재시도, 상세 전환 후 늦게 도착한 응답 무시, 화면 해제 후 재검색 중지, 지도 정리, 내 위치의 별도 버튼 요청을 포함한다. 홈·데모·키 없는 실행의 지도 호출 경계를 유지한다.

## 지도 주변 UI 제거 (2026-09-17, 자동 표시 검증 이후)

후속 사용자 요청에 따라 지도 제목·주소·장소명·성공 메시지와 이름 검색·주소 검색·공식 위치 안내 링크, 내 위치 버튼을 제거했다. 정상 상태는 지도만 표시한다. 장소·주소·주소 좌표의 한계는 화면 읽기용 설명으로 연결하고 미검토 후보는 선택 전까지만 표시한다. 로딩·실패·0건·키 없음은 최소한의 안내를 제공하며 재시도 가능한 실패에는 버튼을 둔다. 지도 영역의 외부 링크 대신 위 관람 안내의 공식 전시 안내를 이용한다. 현재 위치 API는 호출하지 않는다.

전시 `/exhibitions/1`을 새로 열어 지도 타일·마커가 자동으로 나타나고 주변 제목·문구·링크·버튼이 보이지 않음을 실제 화면에서 확인했다. `npm run test -- src/features/map/MapPanel.test.tsx src/app/Product.test.tsx`의 기존 검사 18개와 타입 검사가 통과했다. 자동 지도·실패 재시도·공식 전시 안내 연결을 유지하고 지도 주변 UI 제거와 화면 읽기용 설명을 확인했다.

## 지도 안 조작 버튼 (2026-09-17, 주변 UI 제거 이후)

후속 사용자 요청으로 지도 오른쪽 위에 현재 위치·확대·축소·전시장 위치로 돌아가기 버튼을 추가했다. 주변 제목·주소·외부 링크는 다시 표시하지 않는다. 확대·축소와 복귀는 MapProvider의 지도 인스턴스로 처리한다. 현재 위치는 버튼 클릭 후 한 번 요청하며 요청 중·실패·성공 안내를 지도 안에서 닫을 수 있다. 위치 요청 중 중복 클릭을 막고, 복귀·지도 변경·화면 해제 후 늦게 도착한 위치 응답은 무시한다. 거리·면적·반경 측정 도구는 이번 기본 조작 범위에 포함하지 않았다.

[Kakao 사용자 컨트롤 예제](https://apis.map.kakao.com/web/sample/addMapCustomControl/)의 지도 조작 API를 사용했다. 390px 전환 검증에서 지도 중심이 어긋나는 문제를 확인하여 [영역 크기 변경 계약](https://apis.map.kakao.com/web/sample/mapRelayout/)에 맞게 ResizeObserver로 레이아웃을 갱신하고 마지막 사용자 조작 중심을 유지한다. 지도 해제 시 크기 관찰과 이벤트 연결을 정리한다.

실제 `/exhibitions/1`에서 확대 시 축척 100m → 50m, 축소 및 복귀 시 100m를 확인했다. 데스크톱·390px 화면과 크기 변경 후에도 전시장 마커가 중심에 있고 조작 버튼이 지도 안에 표시됨을 확인했다. 브라우저 크기 설정은 검증 후 복원했다. 실제 사용자 위치 권한은 요청하지 않았으며 현재 위치의 명시적 호출·권한 거부·성공·화면 해제 후 응답 무시는 가상 위치의 컴포넌트 테스트로 검증했다.

`npm run test -- src/features/map src/app/Product.test.tsx` 36개, `npm run typecheck`, 변경한 지도 코드·스타일의 Prettier 검사가 통과했다. 확대 수준 상·하한, 전시장 복귀, 크기 변경 시 중심 유지·관찰 해제, 지도 자동 표시와 데모·키 없는 경계도 포함한다.
