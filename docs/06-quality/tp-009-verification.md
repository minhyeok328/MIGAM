# TP-009 검증 기록

2026-09-07 Windows, main 작업 트리에서 전시 발견과 공식 관람 안내 중심의 초기 출시 조정을 검증했다. 전시 둘러보기·검색·취향 추천·상세·관심·비교를 유지한다. 이 기록은 해당 변경의 로컬 완료 증거이며 전체 P0 검수나 공개 운영 완료를 뜻하지 않는다.

## 반영한 동작

- 추천 UI의 날짜는 전시 기간과 겹치는 후보를 찾는 `exhibition_dates`다. 개관일 확인을 보장하지 않는다. 내부 `visit_dates`는 확인된 개관일을 요구하며, 둘 다 요청하면 두 기간의 교집합을 적용한다.
- 예산·예약·예상 관람시간 입력과 숨은 draft 값을 제거했다. 내부 API의 기존 필수조건과 접근성·감각 정보의 UNKNOWN 제외 규칙은 유지했다.
- 상세·비교에서 확인된 값과 근거는 유지하고 미확인 항목은 공식 전시 상세로 연결한다. 충돌 상태는 함께 안내하며, 확인된 첫 관람일은 실제 날짜가 있을 때만 표시한다. 가상 데모에는 외부 공식 링크를 만들지 않는다.
- 비교는 항목 이름으로 값을 맞춰 첫 관람일이 있는 전시와 없는 전시를 함께 비교해도 행이 어긋나지 않는다.

## 실제 API와 데이터

실제 DB에 연결한 8000 Django API와 5173 Vite를 사용했다. 로컬 상태의 기준일을 갱신하기 위해 기존 `scripts/prepare_local_data.py`를 실행했다. 백업 `data/incoming/backups/db-20260907T065435Z-4991489b.sqlite3`의 무결성을 확인한 후 파생 전시 상태·최신성·검색 문서를 갱신했다. 적용할 migration은 없었으며 전시 758개·기관 9개와 공식 확인 시각을 보존했다. 새 수집이나 관람 정보 확정은 하지 않았다.

- 2026-09-07 현재·예정 검색은 17개다. 전날 종료된 전시가 현재 목록에서 빠졌다.
- `exhibition_dates`를 2026-09-07~2026-09-13, limit를 24로 요청하면 후보 16개·추천 16개다. `visit_availability`가 붙은 결과는 0개다.
- 같은 기간의 엄격한 `visit_dates` 요청은 후보 0개다. 미확인 운영일을 개관으로 추정하지 않는다.
- UI의 기본 limit 6에서는 위 기간에 추천 6개를 확인했다. 전체 DB 수, 현재 검색 수, 기간 후보 수와 한 번에 표시하는 추천 수는 서로 다르다.

브라우저 확인 중 기존 Vite 개발 서버가 종료되어 연결 오류가 발생했다. 8000 API 정상 응답과 5173 연결 거부를 분리 확인한 뒤 Vite를 재기동했고 같은 브라우저 흐름이 정상 완료됐다.

## 브라우저와 공식 링크

Codex In-app Chromium에서 홈의 전시 둘러보기→검색→기간 추천→유영국 상세→비교→공식 전시 안내 연결을 확인했다. 데스크톱과 390×844에서 추천 입력을 점검했고, 모바일 상세·비교의 문구와 링크를 시각 확인했다. 세 화면의 문서 가로 폭은 390px로 화면을 넘지 않았다. 조건 창의 ESC 후 포커스가 ‘자세한 조건’ 버튼으로 돌아왔다. 검증용 비교 선택과 임시 공식 사이트 탭을 정리하고 화면 크기 설정을 복원했다.

대표 공식 링크 4개를 읽어 실제 해당 전시로 연결되는지 확인했다.

## 다음 작업

1. 핵심 발견→상세→공식 안내 흐름을 CI 브라우저 회귀로 고정하고 실제 모바일·200% 확대·보조기술·다른 브라우저를 검수한다.
2. Docker 기동·health·종료, 운영 DB 백업·복구와 수집 주기를 검증하고 공개 호스팅·도메인·운영 설정을 구체화한다.
3. 현재·예정 전시의 관람 정보는 승인된 공식 입력으로 점진 보강한다. 실제 작품 Source 확보와 포괄 P0의 적응형 취향·staff 복구 승인 등은 별도로 진행한다.

위 1·2의 CI 브라우저 실행, 실제 기기·보조기술·다른 엔진, Docker 및 공개 배포는 이번 변경의 실행 범위에 포함하지 않았다. 이번 작업은 main의 미커밋 변경이며 커밋·푸시·공개 배포를 수행하지 않았다.
