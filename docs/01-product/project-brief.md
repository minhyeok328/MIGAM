# 미감(美感) Project Brief

## 1. 문서 목적과 경계

이 문서는 미감의 목적, 대상 사용자, 제품 범위를 정하는 최상위 기초 문서다. 기획 과정에서 확정한 결정을 하나의 제품 방향으로 통합했으며, 모든 하위 문서는 이 문서의 범위와 원칙을 따라야 한다.

이 문서가 정하는 것은 다음과 같다.

- 제품 정체성, 해결할 문제, 핵심 사용자
- 사용자가 얻게 될 핵심 가치와 대표 경험
- 대한민국 우선 원칙과 콘텐츠 범위
- P0·P1·P2의 단계별 범위
- 데이터 신뢰, 개인정보 보호, 접근성에 관한 상위 원칙
- 명시적 제외 범위와 성공 기준

화면별 상세 동작, 컴포넌트 규격, API·데이터베이스 스키마, 수집 작업, 추천 가중치, 테스트 케이스는 이 문서의 범위가 아니다. 이 내용은 각 권한을 가진 하위 문서가 정의하며, 하위 문서가 이 Project Brief의 제품 방향과 비범위를 바꿀 수 없다. 승인되지 않은 하위 문서와 작업 패킷은 코드 구현 권위를 갖지 않는다.

## 2. 제품 요약

### 서비스명

- 한글명: **미감**
- 한자 표기: **美感**
- 영문 표기: **MIGAM**
- 이름의 뜻: 지식의 많고 적음보다 각자가 느끼는 아름다움과 감각에서 출발한다는 의미

브랜드를 강하게 보여주는 자리에서는 `美感`, 일반 UI에서는 `미감`, 영문 보조 표기가 필요한 곳에서는 `MIGAM`을 사용한다.

### 한 문장 정의

> 미감은 사용자의 시각·청각·공간·상호작용 취향과 실제 관람 조건을 바탕으로, 지금 갈 수 있는 국내 전시와 더 탐색할 작품·문화예술 공간을 발견하게 돕는 대한민국 우선 큐레이션 서비스다.

### 핵심 문구

- 메인 슬로건: **당신의 감각으로, 전시를 발견하다.**
- 보조 문구: **아는 만큼 보는 대신, 좋아하는 것부터 시작해보세요.**

### 제품의 중심 약속

미감은 전시 정보를 많이 모아 보여주는 데서 멈추지 않는다. 사용자가 자신에게 맞는 전시를 **발견하고**, 왜 맞는지 **이해하고**, 실제로 갈지 **판단하는** 과정까지 이어 준다.

## 3. 해결하려는 문제

국내 전시 정보는 기관, 공공 데이터, 예매처, 홍보 채널에 흩어져 있다. 사용자는 관심 있는 전시를 발견하더라도 일정, 지역, 가격, 예약, 접근성, 감각 자극 같은 실제 방문 조건을 다시 확인해야 한다. 기존 문화예술 서비스는 작품·작가 지식이나 인기 순위에 치우친 경우가 많아, 자신의 취향을 아직 언어로 설명하기 어려운 사람에게 진입 장벽이 된다.

미감은 다음 문제를 해결한다.

- 무엇을 좋아하는지 정확히 말하지 못해도 감각과 경험을 기준으로 전시를 찾을 수 있어야 한다.
- 날짜·지역·예산·접근성 같은 필수 조건에 맞지 않는 추천을 걸러야 한다.
- 회화뿐 아니라 사운드, 영상, 설치, 퍼포먼스, 인터랙티브·미디어 아트의 경험적 차이를 탐색할 수 있어야 한다.
- 추천 이유와 정보의 출처를 알 수 있어야 하며, 확인되지 않은 내용을 사실처럼 보여주지 않아야 한다.
- 현재 갈 수 있는 전시와 이미 끝난 전시 아카이브를 혼동하지 않으면서도, 과거의 관심이 새로운 발견으로 이어져야 한다.

미감은 전문가용 연구 데이터베이스, 티켓 판매 서비스, 일정 자동 계획 도구를 목표로 하지 않는다. 핵심은 일반 관람자의 **신뢰할 수 있는 발견과 방문 판단**이다.

## 4. 핵심 사용자

### 1차 사용자: 전시 선택이 어려운 일반 관람자

전시 관람을 좋아하거나 관심은 있지만, 수많은 정보 중 무엇이 자신의 취향과 상황에 맞는지 판단하기 어려운 사람이다. 미술사 지식이나 전문 용어를 전제로 하지 않으며, 감각적 선호와 실제 관람 조건부터 선택을 시작한다.

이 사용자의 핵심 과업은 다음과 같다.

> “내가 좋아할 만하면서, 내가 원하는 날 실제로 갈 수 있는 전시를 빠르게 찾고 싶다.”

### 2차 사용자: 문화 외출을 준비하는 동행 관람자

연인, 친구, 가족과 문화 외출을 준비하며 동행 구성, 예산, 이동 지역, 아동·고령자·휠체어 이용자 등 객관적인 조건을 함께 고려해야 하는 사람이다.

이 사용자의 핵심 과업은 다음과 같다.

> “우리의 필수 조건을 놓치지 않으면서, 함께 즐길 가능성이 높은 전시를 비교하고 결정하고 싶다.”

큐레이터, 연구자, 수집가도 서비스를 사용할 수 있지만 제품의 언어와 우선순위는 이들을 기준으로 설계하지 않는다.

## 5. 핵심 가치

### 감각에서 시작하는 낮은 진입 장벽

사용자는 작가나 사조를 몰라도 차분함, 몰입감, 소리, 빛, 움직임, 공간감, 참여성처럼 자신이 느끼고 싶은 경험에서 시작할 수 있다.

### 방문 가능한 추천

지역과 날짜, 사용자가 지정한 최대 예산·필수 접근성·반드시 피해야 할 감각 자극은 선호가 아니라 필수 조건으로 취급한다. 조건에 맞지 않거나 충족 여부를 확인할 수 없는 전시는 주요 추천에서 제외한다.

### 설명 가능한 개인화

취향 테스트와 사용자가 직접 표시한 관심을 근거로 추천하되, 점수나 막연한 문구 대신 실제 추천에 기여한 매체·분위기·경험 특성을 이유로 보여준다.

### 안전한 탐색의 확장

익숙한 취향만 반복하지 않는다. 추천 목록의 일부에는 사용자의 기존 취향과 적어도 하나의 연결점을 가진 새로운 매체·분위기·공간을 섞어 탐색 범위를 넓힌다.

### 출처와 불확실성의 투명성

공식 출처, 마지막 확인 시점, 정보 충돌과 미확인 상태를 숨기지 않는다. 정보가 없으면 추측하지 않고 `확인 필요`로 표현한다.

### 권리와 개인정보를 존중하는 기본값

재사용 권한이 확인된 이미지만 서비스 안에서 사용한다. 사용자 계정을 만들지 않고 취향과 관심 데이터는 기본적으로 사용자의 브라우저에만 보관한다.

## 6. 대표 경험

미감의 경험은 `발견 → 이해 → 판단`의 세 단계로 완결된다.

| 단계 | 사용자 질문 | 미감이 제공하는 가치 |
| --- | --- | --- |
| 발견 | “무엇을 보러 갈까?” | 취향 탐색, 조건 기반 전시 찾기, 통합 검색, 현재·예정 전시 추천 |
| 이해 | “왜 나와 맞고, 실제 관람은 가능한가?” | 추천 이유, 매체·분위기·경험 정보, 가격·예약·접근성·감각 정보, 출처와 최신성 |
| 판단 | “어느 전시를 선택할까?” | 관심 표시, 최대 3개 비교, 선택형 지도 보기, 공식 페이지 연결 |

홈에서는 두 가지 출발점을 같은 중요도로 제공한다.

1. **내 취향부터 알아보기**: 적응형 취향 테스트를 거쳐 자신의 취향 요약과 관련 전시를 탐색한다.
2. **지금 갈 전시 찾기**: 지역과 날짜를 먼저 정하고, 예산·동행·분위기·매체 등 필요한 조건을 더해 현재 갈 수 있는 전시를 찾는다.

미감은 이 결과를 바탕으로 동선을 짜거나 하루 일정을 자동 생성하지 않는다. 최종 선택은 사용자가 관심 표시와 비교를 통해 직접 내린다.

## 7. 제품 원칙

1. **지식보다 감각에서 시작한다.** 전문 지식은 탐색을 돕는 맥락이지 사용 자격이 아니다.
2. **필수 조건과 선호를 분리한다.** 시스템은 사용자가 정한 필수 조건을 몰래 완화하지 않는다.
3. **확인된 사실과 해석을 분리한다.** 주관적 분위기와 감각 특성도 근거가 있을 때만 표시한다.
4. **현재 방문 가능성과 아카이브를 분리한다.** 추천은 진행 중·개최 예정 전시를 중심으로 하고, 종료 전시는 검색과 아카이브에서 다룬다.
5. **개인화의 근거를 설명한다.** 추천 이유는 실제 사용 신호와 콘텐츠 특성에서 생성한다.
6. **다양성은 무작위가 아니라 연결된 탐색으로 만든다.** 새로운 추천에도 사용자가 이해할 수 있는 연결점이 있어야 한다.
7. **권리·출처·최신성은 기능보다 앞선다.** 데이터가 많아도 근거와 사용 권한이 불명확하면 노출 범위를 줄인다.
8. **계정 없이도 완결된 경험을 제공한다.** 개인정보 수집을 기능의 기본 전제로 삼지 않는다.
9. **전국을 수용하는 구조로 만들고, 검증된 지역부터 정직하게 제공한다.** 실제 커버리지를 과장하지 않는다.

## 8. 대한민국 우선 원칙과 콘텐츠 범위

### 지역 범위

데이터 모델과 검색 구조는 대한민국 전역의 시·도와 시·군·구를 수용한다. P0의 검증된 데이터 확보와 품질 보장은 서울·경기·인천을 중심으로 시작한다. 다른 지역의 공식 데이터도 확인되는 범위에서 노출할 수 있지만, 커버리지가 제한적이라는 사실을 사용자에게 명확히 알린다.

### 전시 범위

핵심 대상은 미술관, 박물관, 갤러리, 문화재단·공공 문화공간, 비영리·대안 공간에서 열리는 시각·감각 예술 전시다. 회화, 조각, 공예, 사진뿐 아니라 사운드, 영상, 설치, 퍼포먼스, 인터랙티브·미디어 아트, 디자인, 건축을 포함한다.

아트페어, 비엔날레, 상업적 몰입형 전시, 일러스트·캐릭터 전시, 브랜드 문화 전시, 축제형 전시는 핵심 전시와 구분되는 형식으로 표시할 수 있다. 상품 판매가 중심인 팝업, 포토존만을 목적으로 한 행사, 출처가 불명확한 홍보 행사, 공연·뮤지컬·연극, 강의·교육만으로 구성된 프로그램은 기본 범위에서 제외한다.

### 콘텐츠 객체의 우선순위

P0는 **전시 중심의 하이브리드 구조**를 사용한다.

- 전시: 발견, 추천, 검색, 비교의 중심 객체
- 작품·소장품: 공식 데이터와 사용 가능한 이미지가 확보된 범위에서 취향 탐색과 유사 작품 발견을 지원
- 기관: 방문 정보와 해당 기관에서 열리는 전시의 성격을 파악하는 보조 탐색 축

같은 작가나 기관의 작품이라는 이유만으로 실제 전시 출품작이라고 추정하지 않는다.

## 9. 단계별 제품 범위

P0는 로컬 환경에서 처음부터 끝까지 검증 가능한 핵심 제품이다. P1과 P2는 **향후 후보 범위**이며, 이 문서가 구현을 승인한다는 뜻은 아니다.

### P0 — 신뢰 가능한 전시 발견

- 반응형 한국어 웹에서 취향 테스트와 조건 기반 전시 찾기 제공
- 지역·날짜와 사용자가 지정한 최대 예산·필수 접근성·감각 안전·필수 예약·필수 예상 관람시간 조건을 지키는 현재·예정 전시 추천
- 전시 중심 통합 검색과 필터, 종료 전시 아카이브, 전시·작품·기관 상세 탐색
- 전시·작품·기관을 함께 다루는 `관심 있음`, 최대 3개 전시 비교, 선택형 지도, 공식 페이지 연결
- 실제 근거를 보여주는 개인화 추천과 기존 취향에 연결된 탐색형 추천
- 취향 테스트와 `관심 있음`만 취향 신호로 사용하고, 조회·검색·클릭·체류 시간은 학습하지 않음
- 공식 API와 허용된 공식 기관 자료를 바탕으로 출처·확인 시점·불확실성·이미지 권리 표시
- 전시명·시작일·종료일·장소·지역·유효 상태·공식 상세 URL·공식 출처가 확인된 전시만 최소 품질에 합격시키고, 요금·예약·예상 관람시간·접근성·감각 정보의 미확인은 추론하지 않고 명시적으로 관리
- 후보 기관의 최근 전시 5건 중 4건 이상 `CORE_PASS`를 요구하고 구조적 필드 누락·정책·접근 제한 문제가 있으면 등록을 보류하며, lifecycle은 `CANDIDATE → PROVISIONAL → ACTIVE → SUSPENDED → PROVISIONAL`로 관리
- `PROVISIONAL`도 레코드별 품질·권리·최신성·충돌 게이트를 통과한 데이터는 정상 서비스에 사용하고, 최소 14일·서로 다른 날짜 3회 연속 최종 성공·의미 있는 실제 변경 반영·마지막 실행 성공·정상 Source·미해결 구조 충돌 0건을 증명한 뒤 `ACTIVE`로 승격
- `ACTIVE` 수집 실패 1회는 별도 health를 `DEGRADED`로 두고 우선 재검증하며, 중간 성공 없는 서로 다른 실행 2회 연속 최종 실패 또는 정책·접근·핵심 구조 Critical은 `SUSPENDED`; `PROVISIONAL` Critical은 해당 범위의 수집·승격을 차단하고, 선택 필드 구조 문제는 `UNKNOWN + DEGRADED`, 단건 예외는 레코드 격리
- 전국을 수용하되 수도권과 2023년 1월 1일 이후 전시 및 현재·예정 전시를 우선 검증
- 계정·로그인 없이 취향과 관심을 브라우저에 저장하고 부분·전체 초기화 제공
- 외부 행동 분석 도구 없이 동작하며, 대표 데모 데이터로 핵심 흐름과 예외 상황을 재현
- 웹 자체의 접근성은 핵심 제품 품질로 검증하고, 전시 접근성·감각 정보는 확인 상태를 검증하되 `UNKNOWN`만으로 최소 데이터 품질을 불합격시키지 않음
- 데이터 출처·최신성·충돌·중복·권리를 운영자가 확인할 수 있는 최소 품질 관리 수단 제공

### P1 — 공개 운영과 품질 확장

- 공개 배포와 주기적인 공식 데이터 재검증
- 검증된 전국 기관·공공 데이터와 과거 아카이브의 점진적 확대
- 검색·추천·데이터 품질 운영의 고도화
- 권리가 허용된 미디어를 활용한 시각적 유사성 등 탐색 방식 확장
- P0의 비회원·개인정보 최소화·설명 가능성 원칙 유지

### P2 — 출처 기반 대화형 큐레이터

- 자연어로 전시·작품·기관을 찾고 모호한 취향과 조건을 구체화하는 대화형 탐색
- 현재 브라우저의 취향·관심 정보와 공식 데이터를 요청 시 활용하는 추천·비교
- 답변 근거, 최신성, 미확인 정보를 함께 제시하고 데이터에 없는 사실은 만들지 않는 안전장치

P2의 챗봇은 별도의 사실 체계를 만들지 않는다. P0와 같은 데이터·필수 조건·출처·권리 정책을 따르며 예매·결제나 자동 일정 계획으로 범위를 넓히지 않는다.

## 12. 성공 정의와 지표

### 제품 성공 정의

> 사용자가 전문 지식이나 계정 없이 자신의 취향 또는 관람 조건에서 출발해, 신뢰할 수 있는 현재·예정 전시를 발견하고, 추천 이유와 방문 정보를 이해한 뒤, 관심 표시·비교·공식 페이지 확인으로 스스로 선택을 마칠 수 있다.

P0에는 외부 사용자 분석 도구가 없으므로 클릭률이나 재방문율 대신 검증 가능한 기준으로 성공을 판단한다.

| 영역 | P0 판단 기준 |
| --- | --- |
| 발견 | 두 진입 경로 모두에서 조건에 맞는 현재·예정 전시 후보까지 도달한다. |
| 정확성 | 필수 조건 위반, 종료·취소 전시의 현재 추천 노출, 동일 결과 중복이 0건이다. |
| 이해 | 개인화 추천마다 실제 계산 근거와 일치하는 이유가 하나 이상 있다. |
| 신뢰 | 미확인 정보를 사실처럼 표시하거나 권리 미확인 이미지를 노출하는 사례가 0건이다. |
| 판단 | 관심 저장, 최대 3개 비교, 지도 확인, 공식 페이지 이동까지 연결된다. |
| 접근성 | 이미지 없이 이해하기, 키보드 탐색, 포커스 이동, 모션 감소, 상태의 텍스트 전달을 포함한 핵심 시나리오가 통과한다. |
| 개인정보 | 브라우저에 저장한 취향·관심·최근 기록의 부분 초기화와 전체 삭제가 정상 동작한다. |
| 재현성 | 외부 API 키 없이도 대표 데모 데이터로 핵심 흐름과 주요 예외를 반복 검증할 수 있다. |

공개 운영 이후 행동 지표가 필요해지면 `발견 → 이해 → 판단` 완수 여부만 최소한으로 측정한다. 측정 방식과 보존 정책은 개인정보 원칙에 따라 별도 승인을 받아야 하며, 이를 취향의 암묵적 학습에 사용하지 않는다.

## 14. 변경 불변 조건과 문서 상태

다음 조건을 바꾸려면 Project Brief 자체의 재검토와 승인이 먼저 필요하다.

- 추천의 중심은 진행 중·개최 예정 전시이고, 종료 전시는 아카이브와 취향 근거로 사용한다.
- 사용자의 필수 조건은 자동으로 완화하지 않는다.
- 확인되지 않은 접근성·감각 안전 정보를 긍정으로 간주하지 않는다.
- 추천 이유는 실제 근거와 일치해야 한다.
- 공식 출처와 권리 확인 없이 사실과 이미지를 채우지 않는다.
- 일반 사용자 계정과 서버 개인 프로필을 기본 전제로 삼지 않는다.
- 일정 자동 계획, 예매·결제, 커뮤니티를 인접 기능이라는 이유로 추가하지 않는다.
- 향후 챗봇도 같은 데이터·조건·출처·권리 정책을 사용한다.

현재 버전은 제품 책임자가 승인한 최초 기준선이다. 제품 방향, 범위와 성공 정의의 상위 구현 기준으로 사용할 수 있지만, 실제 구현에는 해당 범위를 직접 정의·검증하는 승인 문서와 작업 패킷이 함께 필요하다. 범위를 바꾸는 새 결정은 이 문서의 버전과 변경 이유에 먼저 반영해야 한다.
