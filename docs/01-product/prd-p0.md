# 미감(美感) P0 Product Requirements

## 1. 문서 목적과 권위 경계

이 문서는 Project Brief가 정한 제품 방향 안에서 **P0 사용자가 무엇을 할 수 있어야 하고, 시스템이 각 상황에서 어떻게 반응해야 하는지**를 정의한다. 기능 요구사항에는 추적 가능한 ID를 부여한다.

`P0-FR-*`는 기능 요구사항, `P0-NFR-*`는 접근성·호환성·운영성·복원력 같은 비기능 요구사항, `P0-OUT-*`는 명시적 비범위다. 각 계열의 번호는 문서 순서가 바뀌더라도 추적 기준으로 유지한다.

이 문서는 화면 배치, 컴포넌트 스타일, API 필드, 데이터베이스 컬럼, 수집기 구현, 추천 가중치를 정하지 않는다. 용어와 불변식은 `domain-rules.md`, 출처와 권리는 `data-source-policy.md`, 데이터 구조는 `data-model.md`, 추천 계산은 `recommendation-spec.md`가 각각 기준이다.

## 2. P0 대상 사용자와 완료 단위

핵심 사용자는 전시 관람에 관심이 있지만 전문 지식이나 익숙한 취향 언어가 부족해 자신에게 맞는 전시를 고르기 어려운 일반 관람자다. 동행자의 연령·접근성·감각 조건과 예산·날짜를 함께 고려해 문화 외출을 정하려는 사용자를 보조 대상으로 포함한다. 관계 유형만으로 적합성을 일반화하지 않고 실제 동행 구성을 확인 가능한 방문 조건으로 다룬다.

P0는 외부 API 키나 사용자 계정 없이 대표 데모 데이터로 핵심 흐름을 반복 검증할 수 있는 반응형 한국어 웹이다. 사용자는 다음 두 경로 중 하나로 시작해 전시 후보를 발견하고, 근거와 방문 정보를 이해한 뒤 관심 표시·비교·지도·공식 페이지를 이용해 판단을 마칠 수 있어야 한다.

1. `내 취향부터 알아보기`
2. `지금 갈 전시 찾기`

두 경로는 서로 독립적으로 시작할 수 있다. 취향 테스트를 하지 않아도 조건 검색과 통합검색을 사용할 수 있고, 방문 조건을 입력하지 않아도 취향과 가까운 현재·예정 전시를 탐색할 수 있다. 방문 조건을 반영하지 않은 결과는 실제 방문 추천이 아니라 취향 유사 후보임을 구분한다.

## 3. 공통 사용자 상태

| ID | 요구사항 |
| --- | --- |
| P0-FR-001 | 일반 사용자는 회원가입·로그인·소셜 로그인 없이 모든 P0 핵심 기능을 사용할 수 있어야 한다. |
| P0-FR-002 | 취향 테스트 결과, 계산된 취향 요약, 전시·작품·기관의 관심 표시, 최근 본 전시는 현재 브라우저에 저장되어 재접속 후 유지되어야 한다. |
| P0-FR-003 | 사용자 개인 프로필을 서버에 생성하거나 장기 저장해서는 안 된다. 추천에 필요한 현재 취향 정보는 요청 처리 범위를 넘어 개인 프로필이나 장기 로그로 축적하지 않는다. |
| P0-FR-004 | 비교 목록, 현재 검색 조건, 검색어, 테스트 진행 단계, 현재 위치 좌표처럼 일시적인 상태는 장기 취향 신호로 저장하지 않는다. |
| P0-FR-005 | 브라우저 저장 데이터에는 스키마 버전을 두고, 읽을 수 없는 버전이나 손상된 값 때문에 서비스 전체가 중단되지 않아야 한다. |

| P0-FR-010 | 현재·예정 전시 소식은 서로 상태를 구분해 탐색할 수 있어야 하며, 개인화 추천과 동일 전시의 중복 노출을 가능한 범위에서 줄여야 한다. |
| P0-FR-011 | 매체별 탐색은 쉬운 상위 분류에서 시작해 해당 조건이 적용된 전시 탐색으로 연결되어야 한다. |

## 5. 취향 테스트와 취향 요약

### 5.1 테스트 진행

| ID | 요구사항 |
| --- | --- |
| P0-FR-012 | 취향 테스트는 기본 약 8문항으로 시작하고, 특정 관심이 발견되거나 신호가 부족할 때만 최대 4~6문항을 추가하는 적응형 흐름이어야 한다. |
| P0-FR-013 | 작품·시각 취향은 복수 카드 선택, 감상 경험은 상황 비교, 매체 세부 취향은 복수 선택을 사용할 수 있어야 한다. |
| P0-FR-014 | 비교 문항에는 `둘 다`와 `잘 모르겠어요`, 모든 문항에는 판단 유보 또는 `건너뛰기` 수단이 있어야 하며, 선택하지 않은 항목을 비선호로 해석해서는 안 된다. |
| P0-FR-015 | 시각 문항에는 서비스 내 재사용이 확인된 실제 작품·전시 이미지만 사용하고, 소리·영상·공간·상호작용은 텍스트와 구조화 정보로 만든 경험 시나리오를 함께 사용해야 한다. |
| P0-FR-016 | P0 취향 테스트에서 실제 음원·전체 영상의 임의 재생, 다운로드, 재호스팅을 요구해서는 안 된다. |
| P0-FR-017 | 사용자는 기본 문항 이후 언제든 결과 보기를 선택할 수 있어야 한다. 고정 문항 수를 완료하지 않았다는 이유만으로 결과 접근을 막지 않는다. |

### 5.2 결과와 재테스트

| ID | 요구사항 |
| --- | --- |
| P0-FR-018 | 완료 화면은 현재 선택에서 자주 나타난 취향과 아직 탐색이 적은 영역을 정성적으로 보여주어야 한다. |
| P0-FR-019 | 취향을 퍼센트나 확정적 성격으로 단정하지 않고, 테스트 선택과 관심 표시 같은 실제 근거를 연결해야 한다. |
| P0-FR-020 | 취향 요약과 현재·예정 전시 후보를 한 흐름에서 확인할 수 있어야 한다. 지역·날짜가 없으면 실제 방문 가능성이 반영되지 않았음을 표시한다. |
| P0-FR-021 | 재테스트 시 최신 테스트 결과를 현재 테스트 기반 취향으로 사용하고 이전 테스트가 현재 추천에 계속 누적되지 않게 해야 한다. 사용자가 해제하지 않은 관심 표시는 유지한다. |

## 6. 지금 갈 전시 찾기

### 6.1 입력 조건

| ID | 요구사항 |
| --- | --- |
| P0-FR-022 | 기본 필수 입력은 지역과 관람 날짜다. 선택 조건은 동행자, 1인 최대 예산, 원하는 분위기, 관심 매체이며 모두 건너뛸 수 있다. |
| P0-FR-023 | 지역은 시·도와 시·군·구를 직접 선택하는 방식을 기본으로 하고, `서울 전체`처럼 넓은 범위도 허용해야 한다. |
| P0-FR-024 | 현재 위치는 사용자가 명시적으로 요청했을 때만 권한을 요청해야 한다. 거부·실패 시에도 수동 지역 선택으로 모든 핵심 기능을 사용할 수 있어야 한다. |
| P0-FR-025 | 날짜 입력은 정확한 하루 또는 사용자가 직접 지정한 시작일·종료일만 제공한다. `오늘`, `이번 주말`, `다음 주` 같은 빠른 기간 프리셋은 제공하지 않는다. |
| P0-FR-026 | 기간 검색은 선택 기간 안에 전시 기간과 겹치면서 확인된 휴관·취소가 아닌 관람 가능일이 하루 이상 있을 때 후보에 포함하고, 실제 가능한 구간과 확인된 휴관일을 구분해 알려야 한다. |
| P0-FR-027 | 예산은 일반 성인 1인의 공식 기본 관람권을 기준으로 `상관없음`, `무료`, 구간별 최대 금액, 직접 입력을 지원해야 한다. |
| P0-FR-028 | 관계 유형은 약한 선호 신호로만 사용한다. 어린이·청소년·고령자·휠체어 이용자 등 실제 동행 구성은 확인 가능한 관람 조건에 사용해야 한다. |
| P0-FR-029 | 분위기는 차분한·몰입형·활기찬·사유형·참여형·실험적 중 최대 3개를 선택할 수 있으며 필수 필터가 아니라 선호로 적용한다. |
| P0-FR-030 | 관심 매체는 쉬운 상위 그룹에서 시작하고 원하는 사용자만 세부 매체를 확장 선택할 수 있어야 한다. 상위 그룹 선택은 약한 선호, 세부 매체 선택은 더 구체적인 선호로 취급한다. |
| P0-FR-031 | 상세 조건에는 공간 유형, 행사 형식, 예약 선호, 어린이·연령 조건, 접근성, 감각 주의, 예상 관람시간을 제공해야 한다. |

### 6.2 필수 조건과 선호

| ID | 요구사항 |
| --- | --- |
| P0-FR-032 | 지역, 날짜, 사용자가 명시한 최대 예산, 필수 접근성, 반드시 피할 감각 조건은 Hard Filter로 처리해야 한다. |
| P0-FR-033 | 분위기, 관심 매체, 관계 유형, 관람시간 선호, 예약 선호, 관심 기관은 Preference로 처리해야 한다. |
| P0-FR-034 | 시스템은 사용자가 정한 Hard Filter를 자동으로 변경하거나 완화해서는 안 된다. |
| P0-FR-035 | 접근성·감각 필수조건의 충족 여부가 공식적으로 확인되지 않으면 안전상 주요 추천에서 제외해야 한다. 이를 `지원하지 않음`으로 단정해서는 안 된다. |
| P0-FR-036 | 요금·예약·관람시간이 미확인인 전시는 조건 충족 후보와 섞어 정상 추천처럼 보여주지 않고 `추가 확인 필요`로 구분할 수 있어야 한다. |
| P0-FR-037 | 매체·분위기 같은 선호 정보가 미확인인 경우 가점도 감점도 하지 않는다. |

## 7. 검색과 전시 탐색

| ID | 요구사항 |
| --- | --- |
| P0-FR-038 | 하나의 통합 검색에서 `전체`, `전시`, `작품·소장품`, `기관` 결과 유형을 분리해 탐색할 수 있어야 한다. |
| P0-FR-039 | 작가명은 전시와 작품의 검색 필드로 지원하되, P0에서 독립 작가 탭이나 작가 상세를 요구하지 않는다. |
| P0-FR-040 | 검색어 없이 전시 탐색에 진입하면 현재·예정 전시를 기본 후보로 하고 종료 전시는 사용자가 상태를 선택했을 때 노출해야 한다. |
| P0-FR-041 | 검색어가 있으면 현재·예정·종료 전시를 모두 검색하되, 관련성 판단 안에서 현재 전시를 종료 전시보다 우선하고 각 상태를 분명히 구분해야 한다. |
| P0-FR-042 | 관련도순은 검색어 일치, 명시 필터, 전시 상태·날짜, 데이터 품질을 개인화보다 우선해야 한다. 개인화는 보조 기준이며 `추천순`에서 더 강하게 반영한다. |
| P0-FR-043 | 전시 필터는 상태, 지역, 날짜·기간, 공간 유형, 행사 형식, 매체, 분위기, 예산, 예약, 접근성, 감각 조건을 조합할 수 있어야 한다. |
| P0-FR-044 | 검색 조건, 필터, 정렬은 URL로 복원 가능해야 하며 새로고침과 상세에서 뒤로 이동했을 때 가능한 범위에서 탐색 상태를 유지해야 한다. |
| P0-FR-045 | 목록은 처음 24개를 보여주고 사용자가 `더 보기`로 다음 24개를 이어 볼 수 있어야 한다. 총 결과 수를 표시하고 필터 변경 시 목록 누적을 초기화하며 중복 결과를 허용하지 않는다. |
| P0-FR-046 | 결과가 0건이면 현재 조건을 보여주고 사용자가 완화할 수 있는 선호 조건만 제안해야 한다. 지역·날짜·접근성·감각 필수조건은 완화 제안에서도 제외하며 예산은 사용자가 직접 선택할 때만 해제한다. |

## 8. 추천 결과

| ID | 요구사항 |
| --- | --- |

## 17. P0 제품 완료 기준

P0의 기능 완료는 다음 결과가 모두 재현될 때 판단한다. 구체적인 테스트 케이스와 실행 명령은 품질 문서가 권위를 갖는다.

- 두 진입 경로에서 현재·예정 전시 후보까지 도달한다.
- 필수조건 위반, 종료·취소·신뢰 불가 전시의 현재 추천, 동일 결과 중복이 발생하지 않는다.
- 개인화 추천 이유가 실제 테스트·관심 신호와 콘텐츠 근거에 일치한다.
- 권리 미확인 이미지를 표시하거나 미확인 정보를 사실처럼 표현하지 않는다.
- 관심 저장, 최대 3개 비교, 선택형 지도, 공식 페이지 연결이 동작한다.
- 키보드·모바일·이미지 없음·외부 출처 실패·로컬 데이터 초기화 시나리오를 완료한다.
- 외부 API 키 없이 대표 데모 데이터로 핵심 흐름을 반복할 수 있다.
