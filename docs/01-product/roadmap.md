# 미감(美感) Product Roadmap

## 1. 문서 목적과 경계

이 문서는 Project Brief에서 정의한 P0·P1·P2를 시간 약속이 아닌 **제품 성숙 단계와 진입 조건**으로 정리한다. 각 단계의 기능 상세는 해당 단계 PRD가 정하며, 이 문서는 일정, 브랜치, 작업 순서, 인력 배분, 호스팅 업체를 확정하지 않는다.

P1과 P2는 승인된 구현 범위가 아니라 향후 후보 범위다. P0 완료가 P1 착수를 자동 승인하지 않으며, 후속 단계에서도 P0의 비회원·필수조건·출처·권리·설명 가능성 원칙을 유지한다.

## 2. 단계 공통 불변 조건

다음 원칙은 별도의 Project Brief 변경 승인 없이 어떤 단계에서도 완화할 수 없다.

1. 추천의 중심은 현재·예정 전시이며 종료 전시는 아카이브로 구분한다.
2. 사용자가 정한 필수 조건을 자동으로 완화하지 않는다.
3. 사용자가 필수 방문 조건으로 지정한 정보의 `UNKNOWN`을 충족으로 간주하지 않는다.
4. 추천 이유는 실제 신호와 콘텐츠 근거에서 생성한다.
5. 출처·확인 시각·미디어 권리가 불명확하면 노출 범위를 줄인다.
6. 일반 사용자 계정과 장기 서버 개인 프로필을 기본값으로 도입하지 않는다.
7. 예매·결제, 자동 일정 계획, 커뮤니티는 인접 기능이라는 이유로 편입하지 않는다.
8. 향후 챗봇도 같은 도메인·데이터·권리 규칙을 사용한다.

## 3. P0 — 신뢰 가능한 로컬 전시 발견

### 3.1 목표

P0의 목표는 계정이나 외부 분석 도구 없이도 사용자가 자신의 취향 또는 방문 조건에서 시작해 신뢰 가능한 전시 후보를 발견하고 판단하는 전체 흐름을 로컬 환경에서 완결하는 것이다.

### 3.2 제품 결과

- 취향 테스트와 조건 기반 찾기의 두 진입 경로
- 현재·예정 전시 추천과 종료 전시 아카이브
- 전시 중심 통합검색, 작품·기관 보조 탐색
- 관심 표시, 최대 3개 비교, 선택형 지도, 공식 페이지 연결
- 공식 출처와 권리를 기준으로 한 데이터·추천 설명
- 브라우저 기반 취향·관심 저장과 사용자의 부분·전체 초기화
- 수도권과 2023년 이후 전시를 우선 검증하되 전국 확장 가능한 구조
- 대표 데모 데이터와 데이터 품질 운영 수단
- 차등 재확인 대상을 처리하는 P0 관리 명령과 동일 경로를 호출하는 배포 스케줄러

### 3.3 P0 내부 성숙 게이트

| 게이트 | 통과 결과 |
| --- | --- |
| G0 문서 기준 | Project Brief와 P0 PRD, 도메인·데이터·추천·품질 기준의 상충이 제거되고 승인 범위가 식별된다. |
| G1 데이터 신뢰 | 데모 데이터와 승인된 출처 데이터가 전시 최소 품질과 원본·권리·최신성·중복 규칙을 통과한다. 기관 후보는 최근 5건 중 4건 이상 `CORE_PASS` 및 구조·정책·접근 예외 검토를 통과하고, `PROVISIONAL`도 레코드 게이트 통과 데이터를 정상 서비스에 사용하며, 14일·서로 다른 날짜 3회 연속 최종 성공·의미 있는 실제 변경 처리·최종 상태 조건을 증명한 뒤 `ACTIVE`로 승격한다. 운영 중에는 lifecycle과 별도 health로 첫 실패·선택 필드 저하를 관리하고, 연속 최종 실패 2회 또는 Critical 사유만 기관을 `SUSPENDED`한다. `PROVISIONAL` Critical은 lifecycle을 늘리지 않고 해당 범위의 수집·승격을 차단한다. 관리 명령과 배포 스케줄러는 같은 차등 재확인 경로를 사용한다. |
| G2 발견 | 두 진입 경로와 통합검색에서 정확한 현재·예정 후보 및 종료 아카이브에 도달한다. |
| G3 이해·판단 | 추천 근거와 방문 정보 확인, 관심, 비교, 지도, 공식 페이지 연결이 완결된다. |
| G4 품질 | 필수조건 위반·권리 위반·근거 불일치가 없고 접근성·브라우저·외부 실패 시나리오가 통과한다. |
| G5 재현성 | 새 환경에서 데모 데이터로 핵심 흐름을 반복 검증할 수 있다. |

### 3.4 P0 종료 조건

P0는 코드가 한 번 실행되는 시점이 아니라 G0~G5의 제품 결과가 모두 재현되고, 공개 운영으로 넘어가기 전에 남은 운영 결정을 식별한 시점에 종료한다. P0 종료만으로 공개 서비스 전환을 승인하지 않는다.

## 4. P1 — 공개 운영과 품질 확장 후보

### 4.1 진입 조건

- P0 제품·데이터·접근성·재현성 기준 통과
- 공개·상업 목적과 저장소·데모 데이터 권리 결정 완료
- 실제 출처 allowlist와 재검증 책임 확정
- 호스팅·비용·관측성 정책 승인

### 4.2 후보 목표

- 공개 배포 환경에서 P0 관리 명령 계약을 이용한 공식 데이터의 주기적 재검증과 관측성 고도화
- 검증된 전국 기관과 과거 아카이브의 점진적 확대
- 검색·추천·데이터 품질 운영의 고도화
- 권리 허용 `source_media_id`와 `model_name`·`model_version`·생성 시각을 추적하는 `VisualEmbedding` 기반 작품 시각 유사성 등 탐색 방식 확장
- 공개 운영에 필요한 최소 관측성과 장애 대응

### 4.3 계속 제외되는 항목

P1은 회원가입·소셜 로그인·익명 서버 프로필·다중 기기 동기화의 자동 도입 단계가 아니다. 사용자 데이터 수집 확대, 외부 행동 분석, 알림, 사용자 콘텐츠, 결제도 별도 제품 결정 없이는 포함하지 않는다.

## 5. P2 — 출처 기반 대화형 큐레이터 후보

### 5.1 진입 조건

- P1에서 공식 데이터와 최신성 운영이 안정적으로 유지됨
- 자연어 응답이 사용할 도메인·검색·추천 계약과 평가 기준이 승인됨
- 답변 출처, 미확인 처리, 권리, 개인정보 경계가 검증됨

### 5.2 후보 목표

- 자연어로 전시·작품·기관을 검색하고 조건을 구체화
- 현재 브라우저의 취향·관심 정보를 사용자가 요청한 대화에서만 활용
- 전시 추천·비교 이유와 공식 출처·최신성·미확인 정보를 함께 제시
- 쉬운 설명이 필요할 때도 데이터에 없는 사실이나 작품 의도를 생성하지 않음

### 5.3 계속 제외되는 항목

챗봇은 별도의 사실 저장소, 예매 대행, 결제, 자동 방문 일정, 장기 개인 프로필을 만들지 않는다. 대화형 기능은 P0/P1의 검색·추천·데이터 정책을 우회할 수 없다.

## 6. 단계 전환 변경 관리

1. 새 단계의 기능은 해당 단계 PRD가 승인되기 전에는 구현 범위가 아니다.
2. Project Brief의 불변 조건을 바꾸는 제안은 Roadmap이 아니라 Project Brief 변경으로 처리한다.
3. 데이터·권리 조건이 해결되지 않은 기능은 일정만으로 다음 단계에 편입하지 않는다.
4. 한 단계의 실험 결과를 다음 단계의 영구 정책으로 간주하지 않는다.
5. 각 단계 문서에는 포함·제외·진입·종료 조건을 함께 기록한다.
