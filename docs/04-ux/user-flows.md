# 미감 P0 사용자 흐름

## 1. 목적과 경계

이 문서는 사용자가 미감에서 `발견 → 이해 → 판단`을 완수하는 순서와 화면 간 전이를 정한다. 화면별 정보 배치와 컴포넌트 상태는 `screen-spec.md`, 시각·접근성 표현은 `ui-guidelines.md`, 합격 조건은 `acceptance-criteria.md`가 맡는다.

아래 UX-001~UX-013은 전체 P0 목표이며 모두 구현된 흐름이 아니다. 현재 [TP-006](../07-execution/task-packets/TP-006-frontend-discovery.md)은 다음 흐름에 한정한다.

- `/`의 API 없는 브랜드 홈 → `전시 둘러보기` → `/discover`의 기본 전시 목록.
- 검색창 제출 → 결과, 또는 필터 열기 → 대상·지역·상태 선택 → 적용 → 조건 칩과 결과. 적용 없이 닫으면 필터 수정은 버린다. 정렬·칩 해제는 미제출 검색어를 전송하지 않는다.
- 홈의 `조건으로 추천받기` → `/discover#recommend` → 조건 입력·추천 → 주요 결과와 확인 필요 후보.
- 검색·추천 입력과 적용 조건은 현재 페이지 메모리에만 두며, 고정 추천 탭 fragment 외에는 URL·브라우저 저장소에 기록하지 않는다. 아래 URL 복원 목표는 현재 구현에 적용하지 않는다.

전체 P0 흐름은 회원가입과 로그인 없이 완결된다. 후속 취향·관심·최근 본 전시 저장은 현재 브라우저에만 한정하며, 서버 개인 프로필이나 기기 간 동기화를 전제로 하지 않는다. 상세·비교·관심·지도·실제 취향 테스트는 별도 승인 후 구현한다.

## 3. 모든 흐름에 적용하는 규칙

| 주제 | 흐름 규칙 |
| --- | --- |
| 추천 대상 | 진행 중·개최 예정 전시만 일반 추천에 포함한다. 종료 전시는 검색·상세·관심·비교·유사 전시 찾기의 기준으로만 사용한다. |
| 최소 데이터 품질 | 전시명·시작일·종료일·장소·지역·유효 상태·공식 상세 URL·공식 출처가 확인된 전시만 사용자 탐색과 추천에 포함한다. |
| 취향 신호 | 취향 테스트와 사용자가 직접 누른 `관심 있음`만 사용한다. 조회·검색·비교·지도·체류 시간은 취향에 반영하지 않는다. |
| 필수 조건 | 지역·날짜와 사용자가 지정한 최대 예산·필수 접근성·회피 감각 조건·필수 예약·필수 예상 관람시간은 자동 완화하지 않는다. |
| 선호 조건 | 동행 관계·분위기·매체·공간 유형·행사 형식과 선호로 지정한 예상 관람시간·예약은 정렬과 설명에 반영한다. 선택하지 않아도 비선호로 해석하지 않는다. |
| 미확인 정보 | 사용자가 필수로 지정한 방문 정보가 `UNKNOWN`이면 해당 조건 추천에서 제외한다. 요금·예약·예상 관람시간의 `UNKNOWN`은 필요하면 별도 `추가 확인 필요`로 표시하되 필수조건 충족으로 세지 않는다. 선호 정보의 `UNKNOWN`은 중립이다. |
| 상태 표현 | `현재`, `예정`, `종료`, `취소`, `최근 확인 필요`, `추가 확인 필요`를 색상만이 아니라 텍스트로 전달한다. |
| 권리 | 재사용 권리가 확인된 이미지만 표시한다. 권리 미확인·링크 전용 이미지는 불러오지 않고 텍스트형 대체 카드를 사용한다. |
| 선택 주체 | 추천과 비교는 판단을 돕지만 최종 전시나 방문 순서를 대신 선택하지 않는다. |

## 4. 진입 경로 A — 내 취향부터 알아보기

`UX-001 홈 → UX-002 취향 테스트 → UX-003 취향 결과·프로필 → UX-004 전시 탐색 또는 UX-006 전시 상세`

1. 사용자는 홈에서 `내 취향부터 알아보기`를 선택한다.
2. 테스트는 기본 약 8문항으로 시작한다. 실제 작품·전시 카드와 경험 시나리오를 혼합한다.
3. 사용자는 복수 선택, 두 상황 비교, 매체 선택을 수행할 수 있다. `둘 다 좋아요`, `잘 모르겠어요`, `건너뛰기`, 중간 `결과 보기`를 허용한다.
4. 선택한 항목만 긍정 신호가 된다. 선택하지 않거나 건너뛴 항목은 부정 신호가 아니다.
5. 응답에 특정 관심이 보이거나 정보가 부족하면 관련 축에서 최대 4~6문항을 추가한다. 최대 문항에 도달하거나 충분한 초기 신호를 얻거나 사용자가 결과 보기를 선택하면 종료한다.
6. 결과 화면은 퍼센트 대신 정성적 취향 요약과 실제 선택 근거를 보여준다.
7. 지역·날짜를 입력하지 않았다면 결과는 `취향이 비슷한 현재·예정 전시`로 표시하며 실제 방문 가능 조건까지 반영한 결과처럼 표현하지 않는다.
8. 사용자가 지역·날짜와 필요한 방문 조건을 추가하면 하드 필터를 적용한 추천으로 전환한다.
9. 전시 카드에서 상세, 관심, 비교, 추가 탐색으로 이어진다.

이미지가 없는 전시는 일반 탐색과 추천에서 제외하지 않지만, 시각적 판단이 필요한 테스트 카드로는 사용하지 않는다. P0 테스트 안에서 오디오·비디오를 직접 재생하지 않는다.

## 5. 진입 경로 B — 지금 갈 전시 찾기

`UX-001 홈 → UX-004 조건 입력·결과 → UX-006 전시 상세 → UX-009 관심 또는 UX-010 비교`

1. 사용자는 홈에서 `지금 갈 전시 찾기`를 선택한다.
2. 필수 입력은 지역과 날짜다.
   - 지역은 시·도, 필요 시 시·군·구를 수동 선택한다.
   - `현재 위치로 찾기`는 사용자가 누른 뒤에만 권한을 요청하며 실패해도 수동 선택으로 복귀한다.
   - 날짜는 하루 또는 사용자가 직접 지정한 기간이다. 빠른 날짜 프리셋은 제공하지 않는다.
3. 사용자는 최대 예산, 동행, 분위기, 관심 매체를 선택할 수 있다. 분위기는 태그와 `UI Guidelines` 8.4의 정본 설명을 함께 보여주며 최대 3개까지 선택하는 소프트 선호다. 예상 관람시간과 예약은 상세 조건에서 각각 `선호` 또는 `필수`로 지정할 수 있고, 공간 유형, 행사 형식, 필수 접근성, 반드시 피할 감각 조건도 여기서 조정한다. 공간 유형과 행사 형식은 분리하고, 행사 형식은 공식 근거가 부족하면 `형식 미확인`으로 표시하며 제목·공간·유사 매체로 추론하지 않는다.
4. 선택한 기간 안에 전시 기간과 겹치면서 확인된 휴관·취소가 아닌 관람 가능일이 하루 이상 있어야 후보가 된다. 일부 날짜만 가능하면 실제 가능한 구간과 휴관일을 명시한다.
5. 예산은 일반 성인 1인의 기본 관람권을 기준으로 판정한다. 할인·얼리버드·패키지 최저가를 대표값으로 사용하지 않는다.
6. 결과 상단에는 적용 조건을 칩으로 보여주고 사용자가 개별 수정·해제할 수 있게 한다.
7. 결과가 0건이어도 필수 조건을 몰래 바꾸지 않는다. 분위기·매체 같은 선호부터 사용자가 선택할 수 있는 조정안을 제안한다. 예산 해제 역시 사용자가 직접 선택할 때만 적용한다.
8. 필수 접근성·회피 감각 조건은 완화 제안에도 포함하지 않는다. 지역·날짜도 유지한다.

## 6. 전시 탐색 흐름

### 6.1 검색어 없이 탐색

`UX-004 진입 → 현재·예정 전시 목록 → 필터·정렬 → 상세 또는 지도`

- 기본 목록은 현재·예정 전시다. 종료 전시는 사용자가 상태 필터에서 선택해야 나타난다.
- 무검색 기본 정렬은 현재 관람 가능, 조건·취향 적합, 종료 임박, 예정 시작 임박, 데이터 품질·완성도 순이다.
- 사용자는 `관련도순`, `추천순`, `최신 시작일순`, `종료 임박순`, `예정 시작일순`을 선택할 수 있다. 상태상 무의미한 정렬은 비활성화하거나 적용 기준을 알 수 있게 투명하게 변환한다.
- 상단 핵심 필터는 지역, 날짜, 상태, 매체, 가격이다. 나머지는 상세 필터 패널에서 제공한다.
- 최초 24개를 보여주고 `전시 더 보기`를 누를 때마다 다음 24개를 이어 붙인다.
- 총 결과 수와 적용 필터를 표시한다. 필터가 바뀌면 추가 로딩 상태를 초기화한다.
- URL은 검색어·필터·정렬을 보존한다. 새로고침 시 조건을 복원하고 상세에서 돌아오면 가능한 범위에서 이미 불러온 목록과 스크롤 위치를 복원한다.
- 같은 전시가 다음 묶음에 다시 나타나지 않는다.

### 6.2 키워드 검색

`UX-005 통합 검색 → 전체·전시·작품·소장품·기관 탭 → 해당 상세`

- `전체` 탭은 유형별 상위 결과를 요약하고 각 유형의 전체 결과로 연결한다.
- 키워드가 있으면 현재·예정·종료 전시를 모두 찾고 상태를 분명히 보여준다. 검색어 일치와 명시 필터를 우선하며, 관련도가 비슷한 결과 안에서 현재, 예정, 종료 순으로 상태를 보정한다.
- 관련도가 기본 우선순위이며 개인화는 보조 신호다. 사용자가 `추천순`을 고르면 검색 조건 안에서 개인화를 더 강하게 반영한다. 사용 가능한 정렬 선택지와 상태상 무의미한 정렬의 처리 규칙은 무검색 탐색과 같다.
- 독립 작가 탭과 작가 상세는 제공하지 않는다. 작가명은 전시·작품 검색 필드로 지원한다.

## 7. 상세 탐색 흐름

### 7.1 전시 상세

`UX-006 전시 상세 → 관심 있음 / 비교 추가 / 기관·작품 상세 / 공식 페이지 / 비슷한 전시`

- 상단에서 전시 상태, 이름, 기간, 장소, 일반 요금, 예약, 주요 매체와 핵심 추천 이유를 확인한다.
- 카드에서는 추천 이유 1개, 상세에서는 실제 계산 기여와 일치하는 이유를 최대 3개까지 보여준다.
- 공식 소개와 미감의 구조화 요약을 구분하고, 출처와 마지막 확인 시점을 제공한다.
- 공식적으로 연결이 확인된 작품만 출품작으로 표시한다.
- 종료 전시는 동일한 정보 구조를 유지하되 `현재 관람 불가`와 과거 방문 정보임을 상단부터 알린다. 행동은 관심, 비교, 유사한 현재·예정 전시 찾기로 이어진다.
- 최소 품질 핵심 항목의 마지막 검증 근거가 남은 `UNVERIFIED` 전시만 일반 추천에서 제외한 채 검색의 `추가 확인 필요` 영역에서 접근할 수 있다. 핵심 항목 누락·무효·충돌 전시는 사용자 검색·상세에 들어오지 않으며 운영 검토로 보낸다.

### 7.2 작품·소장품 상세

`UX-007 작품 상세 → 관심 있음 / 비슷한 작품 / 공식적으로 연결된 전시 / 기관 상세`

- 취향 탐색에 필요한 작품명, 작가, 시대, 매체, 소장기관, 한국 작품·국내 소장 구분과 권리 정보를 제공한다.
- 같은 작가나 소장기관이라는 이유만으로 현재 전시 출품작이라고 추정하지 않는다.
- 작품 관심은 긍정 취향 신호가 되며, 단순 열람은 신호가 아니다.

### 7.3 기관 상세

`UX-008 기관 상세 → 관심 있음 / 현재·예정 전시 / 과거 전시 / 공식 페이지`

- 주소, 운영시간, 휴관, 접근성, 공식 링크 같은 방문 정보를 우선 확인한다.
- 현재·예정 전시와 과거 전시 아카이브를 상태별로 구분한다.
- 기관 성격은 등록된 전시 매체의 집계처럼 근거 있는 정보로만 표현한다. 유명세나 주관적 평가를 생성하지 않는다.

## 8. 관심 흐름

`전시·작품·기관 카드 또는 상세 → 관심 있음 → UX-009 관심 목록 → 관심 해제 또는 다음 탐색`

- `관심 있음`은 브라우저 저장과 중간 강도의 긍정 취향 신호를 함께 수행한다.
- 관심 해제는 해당 긍정 신호를 제거할 뿐 부정 평가가 아니다.
- 관심 목록은 전시, 작품·소장품, 기관의 기본 탭으로 나눈다.
- 관심 전시는 현재 관람 가능, 곧 시작, 종료 상태로 자동 이동한다. 상태가 바뀌어도 관심은 유지된다.
- 종료 전시에서도 상세, 비교, 비슷한 현재·예정 전시 찾기를 제공한다.
- 관심 기관에서는 해당 기관의 현재·예정 전시를 우선 연결하되 그 기관의 모든 콘텐츠를 좋아한다고 해석하지 않는다.
- 사용자 지정 폴더, 공유 목록, 직접 정렬은 제공하지 않는다.

## 9. 비교 흐름

`전시 카드·상세 → 비교 추가 → UX-010 전시 비교 → 전시 제거·상세·공식 페이지`

1. 사용자는 전시를 최대 3개까지 비교에 추가한다.
2. 네 번째 전시를 추가하려 하면 최대 3개임을 알리고 기존 항목을 제거할 수 있게 한다. 자동으로 기존 항목을 교체하지 않는다.
3. 데스크톱은 전시를 열로 둔 비교표, 모바일은 비교 속성을 기준으로 세로 카드·아코디언을 사용한다.
4. 현재·예정 전시는 기간, 장소, 일반 요금, 예약, 관람시간, 매체, 분위기, 접근성, 감각 정보를 비교한다.
5. 종료 전시는 `현재 관람 불가`와 과거 운영 정보임을 고정 안내한다.
6. 값 미확인과 조건 불충족을 다른 상태로 표현한다.
7. 비교는 자동 순위나 최종 선택을 만들지 않는다.

## 10. 선택형 지도 흐름

`UX-004 목록 → 지도에서 보기 → UX-011 지도 → 핀 요약 → UX-006 상세 또는 목록 복귀`

- 목록이 기본이며 지도는 사용자가 선택할 때만 연다.
- 목록과 지도는 같은 검색어·필터·결과 집합을 공유한다.
- 같은 기관의 여러 전시는 기관 핀으로 묶고 전시 수를 표시할 수 있다.
- 핀 요약은 현재·예정 상태, 전시·기관 핵심 정보, 관심, 상세 이동을 제공한다.
- 현재 위치는 사용자가 별도로 요청할 때만 현재 요청에 사용하며 장기 저장하지 않는다.
- 지도 실패, 위치 권한 거절, 좌표 부재가 있어도 목록 탐색은 계속 가능하다.
- 경로, 이동시간 최적화, 교통, 식당·카페, 백그라운드 위치 기능은 제공하지 않는다.

## 11. 최근 본 전시 흐름

`UX-006 전시 상세 열람 → UX-013 최근 본 전시 → 동일 상세 재방문`

- 전시 상세를 연 기록만 최대 10~20개까지 브라우저에 보관한다.
- 같은 전시는 중복 행으로 쌓지 않고 최근 순서를 갱신한다.
- 작품·기관 열람 기록은 만들지 않는다.
- 최근 본 기록은 개인화 추천에 반영하지 않는다.
- 전체 로컬 데이터 삭제 시 함께 제거한다.

## 12. 로컬 데이터 초기화 흐름

`UX-012 내 데이터 관리 → 초기화 종류 선택 → 영향 안내 → 실행 → 관련 화면 갱신`

| 행동 | 삭제 | 유지 |
| --- | --- | --- |
| 취향 테스트 다시 하기 | 기존 테스트 응답과 테스트 기반 결과 | 전시·작품·기관 관심 |
| 관심 목록 초기화 | 전시·작품·기관 관심 | 취향 테스트 결과 |
| 취향 데이터 초기화 | 테스트, 관심, 계산된 취향 프로필 | 일반 UI 설정 |
| 모든 로컬 데이터 삭제 | 취향, 관심, 최근 본 전시, 최근 선택 지역, UI 설정 등 미감의 모든 브라우저 저장값 | 없음 |

- `모든 로컬 데이터 삭제`는 삭제 항목과 복구 불가를 설명하는 확인 대화상자를 거친다.
- 취소하면 어떤 데이터도 바뀌지 않는다.
- 삭제 후 관련 화면과 추천 상태를 즉시 신규 사용자 상태로 갱신한다.
- 서버 계정이나 서버 개인 프로필 삭제 흐름은 존재하지 않는다.

## 13. 로딩·빈 상태·오류 회복

| 상태 | 사용자에게 보여줄 것 | 가능한 다음 행동 |
| --- | --- | --- |
| 최초 로딩 | 영역의 목적을 유지하는 스켈레톤 또는 진행 상태와 읽을 수 있는 상태 문구 | 기다리기, 이전 화면으로 이동 |
| 추가 로딩 | 기존 24개 결과를 유지하고 `전시 더 보기` 위치에 진행 상태 표시 | 중복 클릭 방지, 완료 후 이어서 탐색 |
| 검색 0건 | 현재 조건, 0건 이유, 사용자가 선택할 수 있는 선호 조정안 | 선호 조정, 예산 직접 해제, 검색어 수정 |
| 관심 0건 | 전시·작품·기관 탭별 의미와 탐색 진입점 | 전시 탐색, 취향 테스트 |
| 최근 본 전시 0건 | 기록 방식과 전시 탐색 진입점 | 전시 탐색 |
| 네트워크·서버 오류 | 실패한 영역, 재시도 가능 여부, 유지된 검색 조건 | 다시 시도, 목록·홈으로 이동 |
| 일부 데이터 오류 | 정상 데이터는 유지하고 실패한 영역만 경고 | 해당 영역 재시도, 공식 출처 확인 |
| 지도 오류 | 목록 결과는 유지하고 지도만 사용할 수 없음을 표시 | 목록으로 돌아가기, 지도 재시도 |
| 위치 거절·실패 | 위치를 저장하지 않았음을 알리고 수동 지역 선택 제공 | 지역 직접 선택 |
| 권리 없는 이미지 | 이미지를 요청하지 않고 같은 높이·정보 위계의 텍스트형 카드 표시 | 상세, 관심, 비교 |
| 종료 전시 | 종료 라벨, 과거 정보 경고, 현재 추천 비노출 | 관심, 비교, 비슷한 현재·예정 전시 |
| 공식 취소 전시 | 취소·현재 관람 불가와 공식 확인 근거 | 공식 출처 확인, 검색으로 복귀 |
| `STALE` | 최근 재확인이 필요함과 마지막 확인 시점 | 공식 페이지 확인 |
| `UNVERIFIED` | 최소 품질은 통과했지만 최신 방문 가능성을 확인하기 어렵다는 경고 | 남아 있는 공식 출처 확인, 검색으로 복귀 |

오류가 발생해도 사용자가 입력한 검색어·필터·비교 선택을 가능한 범위에서 보존한다. 시스템은 오류를 숨기기 위해 다른 조건이나 데이터를 임의로 대체하지 않는다.

## 14. 반응형·접근 가능한 흐름

### 모바일

- 홈, 전시, 검색, 관심, 더보기를 하단 내비게이션으로 제공한다.
- 상세 필터는 바텀시트, 비교는 속성별 세로 카드·아코디언으로 제공한다.
- 지도에서 목록으로 돌아가는 경로를 항상 제공한다.
- 모든 핵심 행동은 확대 상태와 터치 입력에서도 가능해야 한다.

### 데스크톱

- 핵심 메뉴와 탐색 드롭다운, 검색 진입을 상단에 제공한다.
- 상세 필터는 우측 패널, 비교는 최대 3열 표로 제공한다.
- 넓은 화면에서도 읽기 순서와 키보드 이동 순서가 시각 순서와 일치해야 한다.

### 공통 접근성 흐름

- 키보드만으로 두 진입 경로, 테스트, 필터, 관심, 비교, 지도 대체 목록, 초기화를 완료할 수 있어야 한다.
- 대화상자·바텀시트·팝오버는 열릴 때 포커스를 내부로 옮기고 닫힐 때 실행한 요소로 돌려보낸다.
- 관심·상태·오류·선택 여부는 색상이나 아이콘만으로 전달하지 않는다.
- 이미지가 없거나 로드되지 않아도 동일한 핵심 정보와 행동에 접근할 수 있다.
- 모션 감소 설정에서는 비필수 전환 효과를 제거하거나 즉시 완료한다.

## 15. 흐름에 존재하지 않는 기능

다음은 어떤 화면에서도 진입점을 제공하지 않는다.

- 일반 사용자 계정, 로그인, 서버 개인 프로필, 기기 간 동기화
- 사용자 컬렉션·폴더·공유, 공개 리뷰·평점·커뮤니티
- `봤어요`, `싫어요`, `관심 없음`과 암묵적 취향 학습
- 티켓 예매·결제·실시간 잔여석 판정
- 일정표·관람 순서·이동 경로·교통·식당·카페·캘린더 계획
- 네이티브 앱, PWA 설치, 오프라인, 푸시, 백그라운드 위치
