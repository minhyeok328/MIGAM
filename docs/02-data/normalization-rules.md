# 미감(美感) Normalization Rules

## 1. 문서 목적과 권위 경계

이 문서는 승인 출처의 다양한 표현을 미감의 정본 도메인 값으로 바꾸는 규칙을 정한다. 출처별 실제 필드 경로와 파서는 OD-003 승인 이후 수집기 문서에서 연결하되, 이 문서의 의미를 바꾸어서는 안 된다.

이 문서는 출처의 허용 여부, 물리 저장 구조, 수집 일정, 추천 가중치와 화면 문구를 정하지 않는다.

정본 분류값의 의미와 포함 범위는 `domain-rules.md`가 단일 기준이다. 이 문서에서 다시 나열하는 값은 원본을 어느 정본값으로 변환할지 판단하기 위한 **매핑 대상**이며 별도의 도메인 정의가 아니다.

## 2. 공통 변환 원칙

1. 원본값과 출처·확인 시각을 보존하고 정규화값으로 덮어쓰지 않는다.
2. 의미가 확인된 범위만 변환한다. 빈 값, 모호한 표현, 파싱 실패를 임의의 기본값으로 바꾸지 않는다.
3. `미확인`, `해당 없음`, `명시적 부정`, `수집 실패`를 서로 다른 상태로 유지한다.
4. 표시용 원문과 비교·검색용 정규화 표현을 분리한다.
5. 직접 공식 근거와 승인 규칙으로 파생한 값은 근거 상태와 규칙 버전을 기록한다.
6. 정규화는 같은 원본과 같은 규칙 버전에 대해 결정적이어야 한다.
7. 한 축의 값으로 다른 축을 추론하지 않는다. 예를 들어 공간 유형으로 행사 형식을, 회화라는 이유로 분위기를 결정하지 않는다.

### 2.1 최소 품질 게이트와 `UNKNOWN`

전시명, 시작일, 종료일, 장소, 지역, 유효 상태, 공식 상세 URL, 공식 출처는 전시 데이터의 최소 품질 핵심 항목이다. 정규화 후 각 항목이 모두 유효해야 합격하며, 누락·파싱 실패·해결되지 않은 충돌을 임의 값으로 보정해 합격시키지 않는다. 유효 상태는 공식 기간·취소 근거에서 `UPCOMING`, `CURRENT`, `ENDED`, `CANCELED` 중 하나를 판정한 상태이며 `UNKNOWN`은 합격값이 아니다.

공식 상세 URL은 해당 전시 한 건을 설명하는 공식 페이지여야 한다. 기관 홈페이지·목록·검색 결과 URL을 상세 URL로 바꾸거나 원본에 없는 경로를 조합하지 않는다. 공식 출처는 출처 등록부의 책임 주체와 FieldEvidence로 별도 확인하며, URL이 있다는 사실만으로 공식 출처 확인을 대신하지 않는다.

요금, 예약, 관람시간, 접근성, 감각 정보는 핵심 게이트 밖이다. 공식 근거가 없으면 각 필드의 상태를 `UNKNOWN`으로 명시하고 값은 만들지 않는다. `UNKNOWN`인 선택 정보만으로 기본 품질을 불합격시키지 않지만, 추천 요청이 그 정보를 필수 방문 조건으로 사용하면 일치 또는 충족값으로 변환하지 않는다.

누락값 추론 금지는 공식 근거에 없는 사실을 대신 만드는 행위를 뜻한다. 공식 주소를 승인 행정구역 코드에 연결하거나 공식 시작·종료일로 생명주기를 계산하는 것처럼 입력 근거와 승인 규칙이 모두 있는 결정적 정규화는 허용하되, 원본·규칙 버전·파생 상태를 추적해야 한다. 이런 파생으로 요금·예약·예상 관람시간·접근성·감각의 누락을 메우지는 않는다.

### 2.2 의미 있는 신규·변경 판정

기관 `PROVISIONAL → ACTIVE` 승격 증거에 쓰는 변화는 원본 응답의 byte·HTML hash가 아니라 같은 승인 정규화 규칙 버전으로 만든 의미 필드 비교 결과다.

다음 흐름을 모두 완료해야 한 건으로 인정한다.

```text
SourceRecord 변경 또는 신규 생성
  → 승인 규칙으로 정규화
  → 의미 필드의 신규·변경 확인
  → Canonical Exhibition 생성 또는 갱신
  → ChangeHistory에 전후 값·SourceRecord·규칙 버전 기록
```

P0 의미 변경 allowlist는 신규 전시, 종료일 변경·연장, 요금 변경, 장소 변경, 예약 방식 변경, 전시 취소, 공식 설명에서 P0 승인·버전 고정 정규화 규칙이 실제 Canonical 필드 변경을 만든 경우로 닫는다. 전시명·시작일·지역·일반 상태 전이를 포함한 목록 밖 값은 그 자체로 승격 증거가 아니며, 범위를 늘리려면 결정 등록부와 이 문서의 규칙 버전을 먼저 함께 갱신한다. 취소만 상태 변경 유형의 명시적 예외다.

페이지 footer·배너, tracking parameter, HTML whitespace·속성 또는 필드 순서, 수집 시각, 재시도 횟수, 정규화 결과가 같은 원본 hash 변화는 의미 있는 변경이 아니다. 이 변화는 SourceRecord와 실행 감사 이력에는 남길 수 있지만 Canonical 필드가 달라지지 않았으면 ChangeHistory의 의미 변경 건수와 승격 증거에 포함하지 않는다.

### 2.3 구조 문제 분류 입력

정규화기는 오류를 기관 lifecycle로 직접 바꾸지 않고 영향 범위와 필드 중요도를 분류해 CollectionIssue 판정 입력을 만든다.

- 최소 품질 핵심 항목 중 하나를 기관·페이지 템플릿 수준에서 안정적으로 추출할 수 없거나 핵심 오값을 대량 생성할 위험, 목록과 상세의 식별 관계 상실이 있으면 `STRUCTURAL_CRITICAL` 후보로 낸다.
- 요금·예약·관람시간·접근성·감각·미디어 필드의 selector·구조만 실패하면 `STRUCTURAL_OPTIONAL` 후보로 내고 값은 `UNKNOWN` 또는 미디어 대체 상태로 둔다. 핵심 필드와 나머지 파이프라인이 정상이라면 레코드는 `CORE_PASS`일 수 있다.
- 가져온 한 전시만 핵심 게이트에 실패하고 템플릿·기관 범위로 재현되지 않으면 `RECORD_EXCEPTION` 후보로 내며 해당 레코드만 격리한다. 같은 핵심 필드·템플릿에서 반복되면 `STRUCTURAL_CRITICAL` 재검토 대상으로 올린다.
- 문제 후보에는 기본 `scope = ENTRY`와 영향 기관·Source·target·field·record 근거를 함께 낸다. 같은 Source 계약·응답 구조가 연결 기관 전체에 동일하게 적용된다는 증거가 있을 때만 운영 검토가 `scope = SOURCE`로 넓힐 수 있으며, 정규화기가 범위를 추정해 자동 확대하지 않는다.

정규화기는 오류를 감추기 위해 기본값을 만들지 않으며, 분류 코드·영향 필드·SourceRecord·규칙 버전과 재현 범위를 함께 보존한다.

## 3. 문자열·이름·별칭

- 앞뒤 공백, 반복 공백, 제어문자와 표시 의미가 없는 공백 변형을 비교 표현에서 정리한다.
- 원래 한글·한자·로마자 표기와 공식 구두점은 표시 이름에 보존한다.
- 대소문자, 전각·반각, 일반적인 유니코드 표현 차이는 비교·검색 표현에서만 통일한다.
- 기관 법인 접두·접미나 전시 제목의 괄호를 의미 확인 없이 삭제하지 않는다.
- 공식 출처가 함께 제공한 한글명·영문명·약칭은 별칭으로 연결할 수 있다.
- 번역명이나 약칭을 임의 생성하지 않는다.
- 동명이인 Creator와 동명 Institution은 이름만으로 합치지 않는다.

## 4. 전시와 작품 제목

- 공식 출처의 대표 제목을 표시 정본으로 보존한다.
- 부제, 회차 표기, 연도 표기, 시리즈 표기는 구조화할 수 있지만 원 제목에서 제거한 값도 보존한다.
- 따옴표·괄호·콜론 차이를 비교 표현에서 완화할 수 있으나 제목 유사도만으로 같은 전시를 확정하지 않는다.
- 작품의 무제 표기는 작가·연도·소장기관과 함께 비교하되 임의 번호를 정식 제목으로 만들지 않는다.

## 5. 지역·주소·좌표

1. 공식 도로명 또는 지번 주소를 원문으로 보존한다.
2. 승인된 공공 행정구역 코드에 시·도와 시·군·구를 연결한다.
3. `서울 전체` 같은 사용자 검색 범위는 여러 행정구역을 묶는 조건이지 Institution의 주소값이 아니다.
4. 행정구역 경계 변경은 코드 버전과 적용 시점을 추적한다.
5. 좌표는 출처·좌표계·정확도 수준을 기록하고 승인된 좌표계로 변환한다.
6. 기관 대표 좌표를 전시실 입구나 정확한 관람 위치로 과장하지 않는다.
7. 주소 또는 좌표가 충돌하면 자동 보간으로 사실값을 만들지 않고 검토 대상으로 남긴다.

## 6. 날짜·시간·생명주기

### 6.1 날짜

- 공식 시작일과 종료일은 한국 표준시의 달력 날짜로 정규화한다.
- 종료일이 시작일보다 앞서면 오류로 격리하고 순서를 자동 교환하지 않는다.
- 월만 있거나 `상반기`, `예정`처럼 범위가 불명확한 값은 정확한 날짜로 생성하지 않는다.
- 전시 기간과 기관 운영시간, 정기 휴관, 임시 휴관, 회차 시간을 분리한다.
- 종료일 포함 여부는 공식 안내가 명시한 범위를 따르며, 일반 전시 기간은 시작일과 종료일을 포함하는 달력 범위로 취급한다.

### 6.2 생명주기

- 공식 취소 확인이 있으면 `CANCELED`를 우선한다.
- 시작 전은 `UPCOMING`, 시작일과 종료일 사이인 경우 `CURRENT`, 종료 후는 `ENDED`로 계산한다.
- 핵심 기간이나 개최 사실을 신뢰성 있게 판정할 수 없으면 `UNKNOWN`이다.
- 수집 실패나 페이지 소실만으로 `ENDED` 또는 `CANCELED`를 만들지 않는다.
- `CURRENT`는 오늘 개관, 특정 회차 가능, 잔여석을 의미하지 않는다.

## 7. 공간 유형과 행사 형식

공간 유형과 행사 형식은 별도 다중값 축으로 변환한다.

### 공간 유형 정본값

- 미술관
- 박물관
- 갤러리
- 문화재단·공공문화공간
- 대안·비영리 예술공간
- 복합문화공간
- 전시 전문 상업공간
- 기타 공식 전시장

### 행사 형식 정본값

- 개인전
- 단체전
- 기획전·특별전
- 상설전
- 아트페어
- 비엔날레·트리엔날레
- 몰입형·체험형 전시
- 브랜드 문화전시
- 축제 연계 전시
- `UNKNOWN` (`형식 미확인`)

공식 분류나 설명의 명시적 근거가 없으면 행사 형식을 `UNKNOWN`으로 남긴다. 제목의 `전`, `아트`, `팝업` 같은 단어, 공간 유형, 매체 또는 유사 전시로 개인전·기획전 등을 추정하지 않는다.

## 8. 매체 정규화

세부 매체를 쉬운 상위 그룹에 연결하되 원본 세부 표현을 보존한다. 하나의 객체는 여러 값을 가질 수 있다.

| 상위 그룹 | 연결 가능한 세부 매체 |
| --- | --- |
| 그림과 평면 작품 | 회화, 드로잉, 판화, 서예 |
| 사진 | 사진 |
| 입체와 공간 | 조각, 설치, 건축·공간 |
| 공예와 디자인 | 도자, 공예, 패션, 제품·시각디자인 |
| 영상과 디지털 | 영상, 애니메이션, 미디어아트, 디지털아트 |
| 소리와 공연 | 사운드 아트, 퍼포먼스, 라이브 미디어 |
| 직접 참여하는 작품 | 인터랙티브, 체험형 설치, 관객 참여형 퍼포먼스 |

상위 그룹만 공식적으로 확인되면 세부 매체를 만들지 않는다. 복합매체를 하나의 대표값으로 축소하지 않는다.

## 9. 주제·분위기·감상 방식

### 9.1 주제

승인 정본값은 자연·생태·환경, 도시·공간·건축, 기술·디지털, 기억·시간, 역사·전통, 사회·정치, 정체성, 몸·감각, 일상, 관계·공동체, 젠더, 노동, 미래·상상, 예술·창작 자체, 기타다.

공식 태그를 우선하고, 공식 제목·소개문에 명시된 표현만 승인된 규칙으로 연결한다. 키워드가 모호하거나 문맥이 부족하면 값을 만들지 않는다.

### 9.2 분위기

사용자-facing 정본값은 차분한·몰입형·활기찬·사유형·참여형·실험적이다.

| 근거 상태 | 부여 조건 |
| --- | --- |
| `DIRECT` | 공식 설명·태그가 해당 경험을 직접 표현함 |
| `DERIVED` | 승인된 객관 조건 조합과 규칙 버전으로 파생됨 |
| `UNKNOWN` | 충분한 근거가 없어 값을 부여하지 않음 |

영상이 있다는 이유만으로 몰입형, 회화라는 이유만으로 차분한, 인터랙티브라는 단어 하나만으로 참여형을 만들지 않는다. 참여형은 관객 조작·센서 반응·참여 퍼포먼스처럼 실제 경험 근거가 필요하다.

### 9.3 감상 방식

소리·영상·공간·상호작용·퍼포먼스 등 확인 가능한 경험 속성을 공식 설명과 구조화 데이터에서 분리해 기록한다. 이를 분위기나 선호 점수로 자동 환산하지 않는다.

## 10. 가격

1. 통화와 금액을 분리하고 원문 가격표를 증거로 보존한다.
2. 일반 성인 1인 공식 기본 관람권을 추천·예산 필터의 대표 가격으로 지정한다.
3. 성인·청소년·어린이·고령자·장애인·기타 우대 대상과 할인 조건을 각각 구조화한다.
4. 얼리버드, 패키지, 도슨트, 체험, 특별 프로그램 가격은 기본 관람권과 분리한다.
5. 전시 입장이 무료이고 선택 프로그램만 유료이면 전시는 무료로 판정한다.
6. `15,000원~25,000원`처럼 범위만 있고 일반 성인 기본권을 식별할 수 없으면 최저값을 대표 가격으로 사용하지 않는다.
7. `무료부터`, `현장 문의`, 조건부 무료처럼 의미가 모호하면 예산 충족값을 생성하지 않는다.
8. 동행자 구성, 할인 자격, 수수료를 사용한 예상 총액을 계산하지 않는다.
9. 일반 성인 기본 관람권을 공식 근거로 확인할 수 없으면 가격 상태를 `UNKNOWN`으로 두고 예산 충족값을 생성하지 않는다.

## 11. 예약

공식 문구를 다음 값으로 연결한다.

| 정본값 | 공식 의미 |
| --- | --- |
| `NOT_REQUIRED` | 예약 불필요 |
| `REQUIRED` | 사전 예약 필수 |
| `RECOMMENDED` | 사전 예약 권장 |
| `TIMED_ENTRY` | 회차별 예약 |
| `ON_SITE` | 현장 접수 |
| `FIRST_COME` | 현장 선착순 |
| `PROGRAM_ONLY` | 일부 프로그램만 별도 예약 |
| `UNKNOWN` | 근거 부족 또는 확인 필요 |

공식 예약 링크와 안내 시각을 별도로 보존한다. 예약 유형에서 현재 잔여석·매진·구매 가능 여부를 추론하지 않는다.

## 12. 예상 관람시간

- 기관의 직접 안내는 `OFFICIAL`과 원문 범위로 기록한다.
- 기관의 직접 안내가 없으면 `UNKNOWN`으로 기록한다.
- 작품 수, 공식 영상 러닝타임, 공간 규모, 유사 전시 또는 평균값을 조합해 관람시간을 만들지 않는다.

## 13. 접근성과 감각 정보

### 13.1 접근성 항목

- 휠체어 접근
- 엘리베이터 등 이동 정보
- 자막
- 수어
- 오디오 설명
- 어린이·연령 조건

### 13.2 감각 주의 항목

- 큰 소리
- 갑작스러운 소리
- 섬광
- 어두운 공간
- 좁거나 밀폐된 공간

각 항목은 공식적으로 확인된 긍정, 공식적으로 확인된 부정, `UNKNOWN`을 구분한다. 안내가 없다는 이유로 접근성을 `미지원` 또는 감각 자극을 `없음`으로 바꾸지 않는다. 기관 일반 정보와 특정 전시 정보를 구분하고, 전시별 명시 정보가 있으면 그 범위에서 우선한다.

## 14. 작품·제작자·기관 관계

- 공식 소장 식별자를 우선해 Artwork를 매칭한다.
- Artwork–Creator는 공식 제작 관계, Exhibition–Creator는 공식 참여 관계로 분리한다.
- Exhibition–Artwork는 공식 출품 목록 또는 동등한 공식 근거가 있을 때만 생성한다.
- 소장기관이 같거나 작가가 같다는 이유로 출품 관계를 만들지 않는다.
- Institution의 운영·주최·개최 장소·소장 역할을 구분한다.

## 15. 미디어와 권리

미디어 원본 URL, 대상 객체, 권리자, 라이선스, 크레딧, 허용 처리, 확인 시각을 분리한다. 표현은 다음 정책 상태로 정규화한다.

- 재사용 허용 확인
- 원본 링크만 허용
- 권리 미확인
- 사용 불가 또는 철회

라이선스 문구를 해석할 수 없거나 대상 파일과 연결되지 않으면 권리 미확인으로 유지한다. 접근 가능한 URL만으로 재사용 허용을 만들지 않는다.

## 16. 중복 비교 표현

중복 탐지에 제공하는 비교 표현은 정본 확정값이 아니다.

### 강한 자동 매칭 후보

- 동일 출처의 안정된 공식 식별자
- 공식 상호 참조 식별자
- 동일 기관·정규화 제목·장소·시작일·종료일이 모두 일치하는 조합

### 검토가 필요한 후보

- 제목과 기간 일부만 일치
- 기관 별칭 또는 주소가 충돌
- 작품명·작가·연도는 같지만 공식 식별자가 없음
- 순회·재개최 가능성이 있는 유사 전시

제목만 같은 경우와 동명이인은 자동 합치지 않는다. 정규화가 구두점·공백 차이를 줄여도 원본 차이는 증거로 보존한다.

## 17. 파생 상태 계산 입력

정규화 단계는 생명주기·최신성·노출 적격성 계산에 필요한 다음 입력만 제공한다.

- 공식 시작·종료·취소 근거
- 마지막 성공 확인, InstitutionRunResult의 최종 성공·실패와 실행 ID
- 핵심 필드 충돌 여부
- 공식성·최소 품질 핵심 항목·권리 검증 결과
- CollectionIssue 분류와 영향 범위, 격리 여부

최종 상태 의미와 노출 규칙은 `domain-rules.md`, 재확인 주기와 계산 시점은 `data-pipeline.md`를 따른다. 한 상태축의 값을 다른 축의 대체값으로 사용하지 않는다.
