# 미감 P0 추천 명세

## 1. 목적과 경계

이 문서는 P0에서 어떤 전시를 추천 후보로 삼고, 어떤 사용자 신호를 사용하며, 결과를 어떻게 다양화하고 설명할지 정한다. 도메인 상태의 의미는 Domain Rules, 데이터 필드는 Data Model, 화면 배치는 UX 문서가 결정한다.

P0 추천의 목적은 사용자가 좋아할 가능성이 높은 항목을 단순히 순위화하는 것이 아니다. **실제 관람 조건을 위반하지 않는 현재·예정 전시 중에서, 취향과 연결되면서도 편중되지 않은 후보를 근거와 함께 제시하는 것**이다.

## 2. 불변 원칙

1. 필수 조건을 만족하지 못한 후보는 취향 점수가 높아도 추천하지 않는다.
2. 사용자가 필수 방문 조건으로 지정한 정보가 `UNKNOWN`이면 충족한 것으로 간주하지 않는다.
3. 전시명·시작일·종료일·장소·지역·유효 상태·공식 상세 URL·공식 출처의 최소 품질 게이트를 통과하지 못한 전시는 후보로 만들지 않는다.
4. 종료·취소 전시는 현재·예정 전시 추천에 섞지 않는다.
5. 취향 테스트와 `관심 있음`만 장기 취향 신호로 사용한다.
6. 조회·검색·비교·지도·공식 링크 클릭·체류시간은 취향 신호가 아니다.
7. 추천 이유는 실제 계산에 기여한 특성과 일치해야 한다.
8. 탐색형 추천은 무작위가 아니라 기존 취향과 한 축 이상 연결되어야 한다.
9. 데이터가 부족하면 정밀한 척하지 않고 일반 추천 또는 `확인 필요`로 안전하게 낮춘다.

## 3. 추천 입력

### 3.1 요청 단위 입력

| 입력 | 역할 | 저장 원칙 |
| --- | --- | --- |
| 지역 | 필수 후보 제한 | 요청 처리 후 개인 프로필로 저장하지 않음 |
| 하루 또는 날짜 범위 | 실제 관람 가능일 판정 | 요청 단위 |
| 사용자가 지정한 최대 예산 | 선택한 경우 필수 후보 제한 | 요청 단위 |
| 필수 접근성 | 선택한 경우 안전 필터 | 요청 단위 |
| 반드시 피할 감각 자극 | 선택한 경우 안전 필터 | 요청 단위 |
| 동행 관계·구성 | 객관 조건은 필터, 관계 유형은 약한 선호 | 요청 단위 |
| 예약·예상 관람시간 | 사용자가 고른 모드에 따라 필수 후보 제한 또는 소프트 선호 | 요청 단위 |
| 분위기·매체·공간 유형·행사 형식 | 소프트 선호 | 요청 단위 |
| 브라우저 취향 프로필 | 콘텐츠 유사도 | 서버 장기 저장 금지 |
| 관심 전시·작품·기관 ID | 명시적 긍정 신호 | 서버 장기 저장 금지 |

### 3.2 콘텐츠 입력

추천은 다음과 같은 검증된 특성을 사용할 수 있다.

- 전시 생명주기와 실제 관람 가능일
- 지역, 기관, 공간 유형, 행사 형식
- 성인 기본 관람권 가격과 예약 상태
- 접근성 지원과 감각 주의 정보
- 매체 상위군·세부 매체
- 공식 근거가 있는 분위기·경험 특성
- 공식 태그 또는 규칙 기반 주제
- 데이터 최신성·완전성·출처 충돌 상태

공식 데이터나 정규화 규칙으로 확보되지 않은 특성은 점수에 기여시키지 않는다. 비어 있는 선호 특성은 불일치가 아니라 중립으로 처리한다.

## 4. 후보 생성과 하드 필터

후보 집합은 최소 품질 게이트를 통과했고 진행 중 또는 개최 예정이며 추천 노출이 허용된 전시에서 시작한다. 정상 Source에 연결된 `PROVISIONAL`과 `ACTIVE` 기관의 레코드는 동일한 품질·권리·최신성·충돌 게이트를 사용하고, `CANDIDATE`·`SUSPENDED`에서 새로 수집·반영된 데이터는 후보에 넣지 않는다. `ACTIVE`는 추천 게이트 우회 권한이 아니며 `PROVISIONAL` 합격 레코드는 상태만으로 배제하지 않는다. 기관 health `DEGRADED`도 후보 일괄 제외 기준이 아니며 레코드별 최신성·품질과 `UNKNOWN` 필드를 적용한다. 요금·예약·예상 관람시간·접근성·감각 정보가 `UNKNOWN`인 사실만으로 최소 품질에 실패시키지는 않지만, 다음 필터에서 사용자가 필수로 지정한 값의 충족 여부는 별도로 판정한다.

| 순서 | 필터 | 통과 조건 | 미확인 처리 |
| --- | --- | --- | --- |
| 1 | 생명주기 | 현재 또는 예정이며 취소 아님 | 추천 제외 |
| 2 | 데이터 품질 | 전시명·시작일·종료일·장소·지역·유효 상태·공식 상세 URL·공식 출처가 확인되고 주요 추천 허용 최신성 상태 | 핵심 항목 미달·검증 불가면 추천 제외 |
| 3 | 지역 | 사용자가 고른 시·도 또는 시·군·구와 일치 | 주소·지역 미확인이면 추천 제외 |
| 4 | 날짜 | 선택한 하루 또는 범위에 실제 관람 가능한 날이 하나 이상 존재 | 핵심 일정 충돌·미확인이면 추천 제외 |
| 5 | 최대 예산 | 지정하지 않았거나 성인 기본권이 상한 이하 | 지정했다면 조건 미충족; 별도 `확인 필요` 영역에는 표시 가능 |
| 6 | 필수 접근성 | 사용자가 지정한 지원 항목을 공식적으로 확인 | 미확인이면 주요 추천 제외 |
| 7 | 감각 회피 | 사용자가 피하려는 자극이 없음을 확인 | 미확인이면 주요 추천 제외 |
| 8 | 필수 예약 조건 | 필수로 지정한 예약 유형과 공식 정보가 일치 | `UNKNOWN`이면 조건 미충족 |
| 9 | 필수 예상 관람시간 | 필수로 지정한 시간 범위를 기관이 직접 안내한 공식값으로 판정 가능 | `UNKNOWN`이면 조건 미충족 |

요금·예약·예상 관람시간처럼 안전과 직접 관련되지 않은 정보의 `UNKNOWN`은 별도의 `추가 확인 필요` 후보군으로 보여줄 수 있다. 그러나 사용자가 해당 값을 필수로 지정한 요청에서 이 후보군은 하드 필터 통과 결과가 아니며 정상 추천과 섞지 않는다. 필수 접근성·감각 안전의 `UNKNOWN`은 이 후보군으로도 우회하지 않는다.

## 5. 취향 프로필과 신호 강도

### 5.1 취향 테스트

취향 테스트는 선택된 매체, 분위기, 공간·감상 경험을 프로필 특성으로 변환한다. `잘 모르겠어요`와 건너뛴 답은 음수 신호로 사용하지 않는다. 테스트를 완료했더라도 지역·날짜가 없으면 결과를 `취향과 가까운 전시`로 표현하고 실제 방문 추천이라고 부르지 않는다.

### 5.2 관심 신호

- 전시 관심: 중간 강도의 긍정 신호
- 작품·소장품 관심: 중간 강도의 긍정 신호
- 기관 관심: 약한 긍정 신호
- 관심 해제: 기존 긍정 신호 제거

종료 전시 관심도 취향 특성을 만드는 데 사용할 수 있지만, 종료 전시 자체를 현재 추천 후보로 만들지는 않는다.

### 5.3 점진적 개인화

| 명시적 데이터 상태 | 추천 동작 |
| --- | --- |
| 취향 테스트·관심 없음 | 최신성과 데이터 품질을 갖춘 일반 추천에 매체·기관 다양성을 적용 |
| 관심 1~2개 | 해당 신호를 약하게 반영하고 과도한 단정 이유를 피함 |
| 관심 3~5개 | 반복되는 매체·분위기·경험 특성을 더 강하게 반영 |
| 취향 테스트 완료 + 관심 축적 | 취향 유사도와 명시적 관심을 함께 사용하되 다양성·탐색 규칙 유지 |

정확한 가중치와 등급 경계는 평가 데이터로 검증하기 전까지 외부 계약으로 고정하지 않는다. 구현은 가중치와 `algorithm_version`을 구성값으로 분리해야 한다.

## 6. 추천 파이프라인

추천은 다음 단계를 순서대로 수행한다.

```text
요청 검증
→ 현재·예정 후보 생성
→ 하드 필터
→ 콘텐츠·취향 유사도
→ 문맥 및 데이터 품질 보정
→ 다양성 재정렬
→ 연결된 탐색 후보 삽입
→ 추천 이유 생성·검증
→ 노출 등급 변환
```

### 6.1 콘텐츠·취향 유사도

사용자가 선택하거나 관심으로 드러낸 매체, 분위기, 경험, 주제 특성과 후보 전시의 검증된 특성을 비교한다. 상위 매체군 선택은 약한 선호, 세부 매체 선택은 더 강한 선호로 취급한다. 선택하지 않은 항목은 비선호가 아니다.

### 6.2 문맥 보정

다음 항목은 기본 유사도에 보정으로 사용할 수 있다.

- 사용자가 명시적으로 관심을 표시한 기관과의 연결
- 사용자가 직접 선택한 세부 매체
- 데이터 완전성·최신성
- 시작 예정일과 종료 임박 여부

인기도나 클릭량은 P0 개인화 보정에 사용하지 않는다.

### 6.3 다양성 재정렬

상위 결과가 같은 기관, 같은 매체, 같은 작가군에 과도하게 몰리지 않도록 재정렬한다. 다양성은 취향 관련성을 없애는 규칙이 아니라 비슷한 점수대 후보 중 편중을 줄이는 규칙이다.

### 6.4 탐색형 추천

대표 추천 6개를 보여주는 맥락에서는 약 1개를 탐색형 후보로 둔다. 탐색형 후보는 다음 중 하나 이상으로 기존 취향과 연결되어야 한다.

- 익숙한 분위기와 새로운 매체
- 익숙한 매체와 새로운 공간·기관
- 익숙한 주제와 새로운 감상 방식
- 관심 작품·전시와 연결되는 다른 시대·분류

연결 이유를 만들 수 없는 후보는 단순 무작위이므로 탐색형으로 노출하지 않는다.

## 7. 작품 유사성과 기관 추천

P0 작품 유사성은 시대, 작가·문화권, 매체, 재료·기법, 주제, 분류, 기관 등 공식 메타데이터만 사용한다. P0에서는 이미지 임베딩을 생성·저장·읽거나 점수에 사용하지 않는다. P1은 재사용이 허용된 `source_media_id`와 `model_name`·`model_version`·생성 시각이 추적되는 `VisualEmbedding`만 시각 유사도에 사용할 수 있으며, 그 결합 방식과 평가는 P1 승인 범위에서 정한다.

기관 관심은 전시·작품 관심보다 약한 신호다. 기관 자체의 유명세보다 해당 기관의 공식 전시 기록에서 반복적으로 확인되는 매체·형식과 현재 전시를 연결한다.

## 8. 추천 이유와 사용자 표시

내부 계산은 비교 가능한 수치 점수를 사용할 수 있지만 사용자에게 퍼센트를 노출하지 않는다. UI에는 다음 정성 수준을 사용한다.

- 취향과 매우 가까워요
- 취향과 잘 맞아요
- 어느 정도 맞아요
- 새롭게 탐색해볼 만해요

등급의 수치 경계는 알고리즘 버전별 구성으로 관리하며 제품 문구의 의미를 바꾸지 않는다.

추천 카드에는 가장 중요한 이유 1개, 상세에는 최대 3개를 보여준다. 이유는 실제 기여 특성에서만 선택한다.

좋은 이유 예시:

- `관심 있게 본 사운드·설치 전시와 매체가 비슷해요.`
- `선호한 차분한 분위기와 공식 전시 설명이 연결돼요.`
- `익숙한 자연 주제를 새로운 인터랙티브 방식으로 탐색할 수 있어요.`

사용하지 않는 이유:

- 근거가 없는 `당신을 위한 완벽한 전시`
- 계산에 쓰지 않은 유명세·인기도
- 확인되지 않은 접근성·관람시간·감각 특성
- 같은 작가·기관이라는 이유만으로 한 출품 추정

각 결과는 최소한 `algorithm_version`, 노출 수준, 기여 특성 식별자, 사용자용 이유를 재현할 수 있어야 한다.

## 9. 결과 0건과 안전한 완화

하드 필터 적용 결과가 0건이면 조건을 자동 변경하지 않는다. 시스템은 현재 조건과 함께 다음처럼 사용자가 직접 바꿀 수 있는 선호만 제안한다.

- 분위기 조건 해제
- 세부 매체를 상위 매체군으로 확대
- 사용자가 선택한 예산 상한 해제

지역·날짜는 사용자가 직접 다시 선택하게 하며, 필수 접근성·감각 회피 조건은 완화 제안에 포함하지 않는다. 사용자가 제안을 선택하면 변경된 조건을 필터 칩에 즉시 표시한다.

## 10. 개인정보와 로그

추천 요청은 브라우저의 취향 특성과 관심 ID를 현재 요청에서만 사용한다. 서버 개인 프로필로 저장하거나 일반 접근 로그·오류 추적에 원문 payload를 장기 보존하지 않는다. 정확한 위치 좌표와 원문 검색어도 추천 학습 데이터로 저장하지 않는다.

개인화 결과의 재현에 필요한 운영 로그가 필요하면 개인 식별이 불가능한 `algorithm_version`, 후보 수, 필터 단계별 제외 건수, 익명 품질 오류 코드만 사용한다.

## 11. 오류와 안전한 저하

- 취향 데이터 파싱 실패: 일반 추천으로 전환하고 브라우저 데이터 초기화 안내 제공
- 일부 콘텐츠 특성 누락: 해당 축을 중립으로 처리하고 다른 근거만 사용
- 데이터 충돌: 방문 핵심 정보 충돌이면 주요 추천 제외
- 권리 허용 이미지 없음: 결과는 유지하고 텍스트 대체 카드 사용
- 후보 부족: 같은 전시를 중복 채우지 않고 실제 개수만 표시
- 추천 서비스 실패: 필수 조건을 적용한 비개인화 기본 정렬로 안전하게 전환

### 11.1 TP-005 물리 계약

`TP-005`는 추천을 `POST /api/internal/v1/recommendations/`의 일회성 요청으로 구현한다. 현재·예정, `VERIFIED`, `FRESH | STALE`, 공식 SourceRecord, 미해결 충돌 없음이 후보 입구 조건이며, 하드 필터가 점수보다 먼저 실행된다. 가격·예약·관람시간의 필수값 미확인은 안전 조건과 알려진 조건을 통과한 경우에만 주요 추천과 분리된 `needs_verification`으로 반환할 수 있다. 접근성·감각 미확인은 이 별도 후보군으로도 우회하지 않는다.

콘텐츠 특성은 Exhibition별 현재 `ContentFeatureSnapshot`의 근거 있는 assertion만 사용한다. snapshot이 없거나 선택하지 않은 축은 중립이다. 응답은 알고리즘 버전, 정성 등급과 실제 양의 기여 이유를 제공하지만 내부 점수·퍼센트를 제공하지 않는다. 정확한 요청 필드, 근거 선택, 점수·다양성 상수와 제외 범위는 승인 작업 패킷 [`TP-005`](../07-execution/task-packets/TP-005-explainable-recommendation.md)가 정한다.

## 12. 열린 결정 영향

- `OD-003`: `RESOLVED`. 승인 allowlist의 초기 커버리지는 서울 4개 기관·경기 1개 기관이며, 추천 평가 데이터는 [`source-qualification.json`](../../fixtures/source-qualification.json)의 판정 결과를 반영한다.
- `OD-005`: 외부 공개 API를 제공하면 추천 요청의 인증·오남용 방지·버전 지원 정책이 추가로 필요하다.
- `OD-006`: P1 운영 환경이 정해져야 장기 성능·관측성 기준을 확정할 수 있다.

이 열린 결정은 P0 추천 원칙을 바꾸지 않는다.
