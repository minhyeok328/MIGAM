# 미감 추천 품질 평가 명세

## 1. 목적

이 문서는 추천이 그럴듯해 보이는지가 아니라 확정된 필수 조건, 데이터 신뢰, 설명 가능성, 다양성 원칙을 실제로 지키는지 평가한다. P0에는 외부 사용자 Analytics가 없으므로 출시 판단은 재현 가능한 고정 평가 데이터와 핵심 시나리오를 중심으로 한다.

## 2. 평가 계층

| 계층 | 질문 | 방법 |
| --- | --- | --- |
| 단위 평가 | 필터와 점수 단계가 개별 규칙을 지키는가? | 고정 입력과 예상 출력 비교 |
| 시나리오 평가 | 여러 조건이 겹쳐도 안전한 결과를 내는가? | 합성 사용자·전시 fixture |
| 결과 집합 평가 | 중복과 기관·매체 편중이 없는가? | 상위 결과 집합 분석 |
| 이유 평가 | 사용자 문구가 실제 기여 근거와 일치하는가? | 계산 trace와 이유 코드 대조 |
| 회귀 평가 | 알고리즘 변경이 기존 안전 조건을 깨지 않는가? | 버전 간 고정 평가셋 비교 |
| 사람 검토 | 탐색형 연결과 문구가 이해 가능한가? | 근거를 가린 독립 검토표 |

## 3. P0 필수 통과 게이트

| ID | 게이트 | 통과 기준 |
| --- | --- | --- |
| REC-GATE-001 | 하드 필터 안전성 | 지역·날짜·선택 예산·필수 접근성·감각 회피와 사용자가 필수로 지정한 예약·예상 관람시간 위반 또는 `UNKNOWN` 통과 0건 |
| REC-GATE-002 | 생명주기 정확성 | 현재·예정 추천에 종료·취소 전시 0건 |
| REC-GATE-003 | 검증 상태 정확성 | 주요 추천에 검증 불가 전시 0건 |
| REC-GATE-004 | 중복 방지 | 동일 전시 또는 병합되어야 할 중복 노출 0건 |
| REC-GATE-005 | 이유 일치 | 노출 이유와 실제 기여 특성 불일치 0건 |
| REC-GATE-006 | 권리 안전성 | 권리 미확인 이미지 노출 0건 |
| REC-GATE-007 | 신호 제한 | 조회·검색·비교·클릭·체류시간에 따른 순위 변화 0건 |
| REC-GATE-008 | 조건 불변성 | 0건 처리에서 사용자 선택 없이 필수 조건 변경 0건 |
| REC-GATE-009 | 후보 정직성 | 후보 부족 시 중복·종료 항목으로 개수를 채우는 사례 0건 |
| REC-GATE-010 | 재현성 | 같은 데이터·요청·알고리즘 버전은 같은 결과와 이유를 생성 |
| REC-GATE-011 | 최소 데이터 품질 | 전시명·시작일·종료일·장소·지역·유효 상태·공식 상세 URL·공식 출처 중 하나라도 미달한 추천 후보 0건 |

하나라도 실패하면 추천 관련 P0 완료로 판단하지 않는다.

## 4. 고정 평가 데이터 구성

평가 fixture는 다음 사례를 의도적으로 포함해야 한다.

- 현재, 예정, 종료, 취소, 상태 미확인 전시
- 하루 검색, 기간 겹침, 휴관일만 겹치는 전시
- 무료, 성인 기본권 상한 이하·초과, 가격 미확인 전시
- 휠체어·엘리베이터·자막 등 지원 확인·미확인·미지원 조합
- 섬광, 큰 소리, 암전, 좁은 공간 등 감각 정보 조합
- 사운드·영상·설치·퍼포먼스·인터랙티브와 전통 매체의 혼합 전시
- 같은 기관·같은 매체가 과도하게 몰린 후보군
- 공식 동일 ID 중복과 제목 유사하지만 다른 순회전
- 권리 허용·링크 전용·권리 미확인·이미지 없음 사례
- 공식 정보와 파생 분위기, 분위기 미확인 사례
- 출처 충돌, 오래된 정보, 일시적 수집 실패 사례
- 최소 품질 핵심 항목을 하나씩 누락한 사례와, 요금·예약·예상 관람시간·접근성·감각 정보만 모두 `UNKNOWN`인 합격 사례

평가 데이터는 운영 데이터를 그대로 복제하지 않고 가상 이름과 권리 안전 자산을 사용한다.

## 5. 핵심 시나리오

### REC-SC-001: 취향 데이터 없는 첫 방문

조건: 취향 테스트와 관심 없음, 서울의 실제 관람 가능 날짜 지정.

기대:

- 현재·예정이며 데이터 품질이 충분한 전시만 포함
- 동일 기관·매체 편중이 완화됨
- 개인화된 것처럼 단정하는 이유를 사용하지 않음
- 결과가 부족하면 실제 개수만 표시

### REC-SC-002: 사운드·몰입 취향 사용자

조건: 사운드·설치 관심과 몰입 경험 선호, 예산 제한 없음.

기대:

- 검증된 사운드·설치 특성이 주요 기여 근거가 됨
- 사운드를 선택하지 않았다는 이유로 다른 매체를 음수 처리하지 않음
- 탐색 후보는 익숙한 분위기 또는 주제로 연결됨

### REC-SC-003: 휠체어 접근 필수

조건: 휠체어 접근 필수.

기대:

- 지원 확인 전시만 주요 추천에 포함
- 미확인과 미지원 전시는 포함하지 않음
- 결과 0건이어도 접근 조건 완화 버튼을 제안하지 않음

### REC-SC-004: 섬광 회피 필수

조건: 섬광 반드시 피하기.

기대:

- 섬광 있음 또는 정보 미확인 전시는 주요 추천에서 제외
- 매체·분위기 점수가 높아도 예외 없음

### REC-SC-005: 예산 지정과 가격 미확인

조건: 일반 성인 기본권 최대 10,000원.

기대:

- 무료·10,000원 이하만 주요 추천
- 가격 미확인은 `추가 확인 필요`로 분리할 수 있으나 주요 추천에 섞지 않음
- 얼리버드 최저가를 성인 기본권처럼 사용하지 않음

### REC-SC-006: 종료 전시 관심 활용

조건: 종료된 미디어 아트 전시에 관심 표시.

기대:

- 종료 전시의 특성은 현재·예정 후보 점수에 기여 가능
- 종료 전시 자체는 현재 추천 결과에 포함되지 않음

### REC-SC-007: 암묵 행동 비학습

조건: 같은 사용자가 특정 전시를 여러 번 조회·검색·비교하고 공식 링크를 클릭.

기대:

- 취향 테스트와 관심 데이터가 같으면 추천 점수와 이유가 변하지 않음

### REC-SC-008: 데이터 충돌

조건: 공식 API와 기관 페이지의 종료일 또는 휴관 정보가 충돌.

기대:

- 충돌이 해결되지 않은 동안 주요 추천에서 제외
- 검색 노출 시 충돌·확인 필요 상태를 숨기지 않음

### REC-SC-009: 필수 예약·예상 관람시간과 `UNKNOWN`

조건: 사용자가 예약 유형 또는 예상 관람시간 범위를 필수 방문 조건으로 지정.

기대:

- 해당 값이 `UNKNOWN`인 전시는 조건 충족 후보로 계산하지 않음
- 같은 조건을 선호로 지정하면 `UNKNOWN`은 가점·감점 없이 처리하고 확인 필요 상태를 숨기지 않음
- `UNKNOWN`을 유사 전시나 평균값으로 채워 추천 이유에 사용하지 않음

## 6. 다양성과 탐색 평가

대표 추천 6개에서는 다음을 검토한다.

- 동일 기관이 불필요하게 결과 대부분을 차지하지 않는가?
- 같은 매체만 반복될 때 비슷한 관련도의 다른 매체 후보가 있는가?
- 탐색형 후보 약 1개가 기존 취향과 한 축 이상 연결되는가?
- 탐색형 이유가 단순히 `새로워서`가 아니라 매체·분위기·주제·기관 연결을 설명하는가?
- 다양성 재정렬이 필수 조건이나 높은 관련성을 깨뜨리지 않는가?

후보 풀이 한쪽으로 편중되어 목표 구성을 만들 수 없으면 억지로 채우지 않고 `후보 제약`으로 평가 보고서에 기록한다.

## 7. 추천 이유 검증

각 추천 결과에 대해 다음을 자동 대조한다.

1. 사용자용 이유가 가리키는 특성 식별자가 존재한다.
2. 해당 특성이 후보 데이터에서 검증된 값이다.
3. 해당 특성이 현재 계산에서 실제 양의 기여를 했다.
4. 미확인·충돌·권리 제한 특성을 이유로 사용하지 않았다.
5. 카드 이유 1개, 상세 이유 최대 3개 제한을 지킨다.

사람 검토자는 사용자 문구만 보고 다음에 답한다.

- 어떤 취향과 연결됐는지 이해할 수 있는가?
- 사실과 추천 해석이 구분되는가?
- 지나친 확신이나 전문 용어가 없는가?
- 탐색형 후보가 무작위처럼 느껴지지 않는가?

## 8. 버전 회귀 비교

알고리즘 변경 시 같은 고정 평가셋에 대해 이전 `algorithm_version`과 새 버전을 함께 실행한다. 다음 변화는 명시적인 검토 사유가 필요하다.

- 필수 통과 게이트의 신규 실패
- 주요 추천에서 검증 불가 데이터 증가
- 이유 코드가 없는 결과 증가
- 상위 결과의 기관·매체 편중 악화
- 콜드 스타트 결과 다양성 감소

점수 순서 변화 자체는 실패가 아니다. 안전 조건, 설명 가능성, 다양성이 나빠졌는지를 기준으로 판단한다.

## 9. 평가 보고서 최소 형식

```text
algorithm_version:
dataset_version:
executed_at:
gate_results:
scenario_results:
hard_filter_violations:
lifecycle_violations:
duplicate_results:
reason_mismatches:
rights_violations:
diversity_observations:
known_dataset_constraints:
reviewer:
decision:
```

`decision`은 `PASS`, `FAIL`, `REVIEW_REQUIRED` 중 하나다. 필수 통과 게이트가 실패하면 항상 `FAIL`이다.

## 10. 운영 지표와의 경계

P0 추천 평가는 외부 클릭률, 체류시간, 전환율을 필요로 하지 않는다. 향후 최소 행동 측정이 승인되더라도 해당 이벤트는 제품 흐름 평가용이며 취향 학습 신호로 사용하지 않는다.

`OD-003`은 해결됐으며 실제 출처의 지역·기관 편중 평가는 [`source-qualification.json`](../../fixtures/source-qualification.json)의 서울 4개 기관·경기 1개 기관 구성을 기준으로 시작한다. `OD-006`이 해결되기 전에는 운영 트래픽 기반 성능 목표를 이 문서에서 확정하지 않는다.

## 11. TP-005 자동 평가 증거

`tests/discovery/test_recommendation_service.py`는 `REC-GATE-001`~`005`, `007`~`011`의 서비스 경계를 고정 fixture로 검증한다. `tests/discovery/test_recommendation_api.py`는 공식 출처·권리 안전 presentation, 점수 비노출, 요청 신호 비영속과 정상 0건을 검증하고, `tests/discovery/test_content_features.py`는 이유의 입력이 되는 현재 feature assertion의 출처·규칙 이력을 검증한다. 같은 입력의 순서·등급·이유 재현성과 12개 후보의 고정 쿼리 상한도 자동 확인한다.

OperatingSchedule이 아직 없어 공식 휴관일을 포함한 실제 관람 가능일 시나리오, 외부 Source에서 만든 전체 feature snapshot 백필, 대표 300~500건 데이터셋과 사람 문구 검토는 완료 근거에 포함하지 않는다. 따라서 TP-005는 승인 패킷 범위의 자동 게이트를 구현하지만 P0 전체 추천 평가의 최종 `PASS`를 뜻하지 않는다.
