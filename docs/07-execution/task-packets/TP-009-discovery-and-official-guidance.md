# TP-009 전시 발견과 공식 관람 안내

## 승인과 범위

2026-09-07 사용자가 전시 둘러보기 유지, 관람 정보가 부족한 필터 제외, 전시 기간 탐색과 공식 안내 연결의 수정안을 확인한 뒤 ‘그렇게 작업 시작하자’로 구현을 승인했다. main에서 기존 데이터와 변경을 보존한다. 전시 둘러보기·검색·취향 추천·상세·관심·비교는 유지한다. 전체 P0 완료나 공개 배포 승인은 아니다.

## 계약

- 추천에 `exhibition_dates`를 추가한다. 공식 전시 기간과 inclusive overlap을 검사하며 개관을 보장하지 않는다. 기존 `visit_dates`는 엄격한 개관일 판정이며 둘 다 있으면 교집합에 적용한다. 역전·잘못된 날짜는 400, 서로 겹치지 않는 유효 조건은 0건이다.
- 기본 UI는 전시 기간만 전송한다. 예산·예약·예상 관람시간 필드와 숨은 draft 값을 제거한다. 내부 API의 기존 필수조건은 보존하고 접근성·감각 조건도 유지한다.
- 상세·비교의 확인된 값은 근거와 함께 표시한다. 미확인 항목은 공식 전시 상세로 연결하고 충돌은 별도 안내한다. 확인된 예약 URL만 예약 링크로 사용한다. 데모에는 가상 공식 링크를 노출하지 않는다. 첫 관람일 행은 실제 날짜가 있을 때만 표시한다.
- 출처·권리·최신성 게이트를 유지하며 데이터 수집·키·비용·계정·공개 배포를 확장하지 않는다. 실제 관람 정보의 전체 확보는 초기 출시 선행 조건에서 제외하고 점진적으로 보강한다.

## 실행과 검증

- [x] 백엔드: recommendation 요청·검증·기간 판정, OpenAPI 1.5.0, inclusive 경계·UNKNOWN·엄격한 방문일·교집합·잘못된 날짜 API 테스트.
- [x] 프론트: forms·RecommendationPanel·ConditionDialog에서 요청과 입력 정리, DetailPage·ComparePage의 공식 안내 연결, 홈/둘러보기 유지 회귀와 입력→API·상세→안내 테스트.
- [x] 통합: 생성 타입 일치, 관련 테스트·공통 계약 회귀·빌드·형식 검사, 실제 공식 링크 읽기 확인과 데스크톱·390px 브라우저 흐름 확인.
- [x] 문서: 실제 검증 결과와 링크 확인의 제한, 다음 우선순위를 기록한다.

2026-09-07 완료 증거와 범위의 한계는 [TP-009 검증 기록](../../06-quality/tp-009-verification.md)에 기록했다. 공개 배포와 전체 P0 검수 완료를 뜻하지 않는다.

백엔드 구현과 직접 관련 테스트·OpenAPI는 독립 에이전트 1명에게만 위임하고, 루트가 소유 문서·프론트·통합 검증을 담당한다. 같은 파일의 동시 수정·재위임·별도 브랜치·자동 커밋/푸시는 하지 않는다.
