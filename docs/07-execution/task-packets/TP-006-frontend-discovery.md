# TP-006 프론트엔드 홈과 검색·추천 분리

## 목적과 승인 근거

기존 검색·추천 내부 API를 한국어 반응형 화면에서 사용할 수 있게 하고, API와 사용자 입력을 소유하지 않는 브랜드 홈을 별도 경로로 분리한다. 최초 승인일은 2026-09-03이다. 2026-09-04의 1.1.0은 한 화면 안의 에디토리얼 도입부를 승인했으나, 같은 날 최신 사용자 결정으로 `/`의 몰입형 홈과 `/discover`의 정보형 탐색을 분리하는 2.0.0으로 대체됐다. 승인 범위는 이 패킷에 한정하며 포괄 UX·기술 문서의 검토 상태는 유지한다.

## 포함 범위

- `frontend/`: npm·lockfile, React·TypeScript·Vite, Tailwind CSS, Lucide React, TanStack Query, Zustand.
- 복합 primitive는 **Radix 직접 사용**으로 통일한다. 탭은 Radix Tabs, 상세 조건은 Radix Dialog의 데스크톱 우측 패널/모바일 바텀시트로 구현한다. 일반 입력·선택·체크는 native form control을 사용한다.
- `/`는 discovery provider와 API를 마운트하지 않는 브랜드 홈이다. `美感` 워드마크, 하나의 페이지 `h1`, 풀스크린 홈 필름, 미감의 관점, `공간의 온도`·`머무는 시선`·`재료의 감각` 시각 챕터, `/discover`와 `/discover#recommend`로 이동하는 두 CTA만 제공한다.
- `/discover`는 기존 `전시 둘러보기`·`조건으로 추천받기` 탭, 검색·추천 입력과 API 결과만 소유한다. 홈 히어로·브랜드 선언문·장식 챕터를 반복하지 않으며 미구현 메뉴·상세·관심 버튼은 노출하지 않는다.
- 두 경로는 실제 `<a href>` 문서 이동을 사용한다. `/discover#recommend`의 고정 fragment만 비민감한 초기 탭 선택자로 허용하고, 두 고정 경로를 위해 라우터 의존성이나 자체 history 라우터를 추가하지 않는다. 나머지 경로는 접근 가능한 404 안내와 두 유효 경로 링크를 제공한다.
- 홈에는 하나의 가상 미술관처럼 통일한 자체 생성 16:9 장면 6개를 사용한다. 자연광, 작은 가상 관람객의 뒷모습, 한지·도자·무광 금속, 유리와 그림자를 웜 아이보리·먹색·석회색·흐린 청회색·옅은 흙색으로 표현한다. 실존 인물·작품·기관·브랜드·읽을 수 있는 문구·로고·워터마크는 넣지 않는다.
- 여섯 장면은 약 10~12초 무음 MP4·WebM 루프와 WebP poster로 제공한다. 영상은 장식이며 `muted`, `autoPlay`, `loop`, `playsInline`, `preload="metadata"`를 사용한다. `prefers-reduced-motion: reduce`, 모바일 우선 표시, 로딩·재생 실패에서는 poster만으로 같은 메시지와 CTA가 성립해야 한다.
- 홈 생성 자산은 실제 전시·작품·기관을 나타내지 않으며 빈 대체 텍스트 또는 접근성 트리 제외를 사용하고 전시 데이터·추천 근거·`MediaAsset`에 연결하지 않는다. 기존 갈색 v1 추상 이미지는 기록용으로 보존하되 런타임에서 참조하지 않는다.
- 검색: 전시·기관·전체 유형, 검색어, 지역, 상태, OpenAPI 허용 정렬, 24건씩 더 보기. 입력 변경은 명시적 검색 실행 전까지 결과에 적용하지 않는다. 새 요청은 페이지를 초기화하고 늦게 끝난 이전 요청이 새 결과를 덮지 않는다.
- 추천: 시·도/시·군·구, 방문 시작·종료 날짜, 0을 포함한 최대 예산, 필수 접근성, 피할 감각 자극, 예약 유형·관람시간의 선호/필수, 분위기 최대 3개. 예약·관람시간 기본 모드는 선호이며 값을 선택하기 전에는 보내지 않는다.
- 분위기 UI 코드는 `CALM`, `IMMERSIVE`, `LIVELY`, `REFLECTIVE`, `PARTICIPATORY`, `EXPERIMENTAL`을 `MOOD` 축으로 보내고 UI Guidelines 8.4의 이름·설명을 사용한다. 이 매핑은 사용자 명시 선호의 표현일 뿐 전시의 특성을 생성·추론하지 않는다.
- 추천은 기본 6건, 주요 추천과 가격/예약/시간 확인 필요 후보를 별도 구역으로 표시한다. 카드에는 서버가 준 첫 번째 실제 이유와 정성 등급만 표시한다. 점수·퍼센트·임의 추천 이유는 만들지 않는다.
- 검색 결과는 비교와 빠른 판독을 우선하는 `catalog` 카드로, 주요 추천과 확인 필요 후보는 발견의 리듬을 살린 `editorial` 카드로 표현한다. 두 변형은 같은 데이터·미디어 권리·출처·텍스트 대체 계약을 공유한다.
- 전시 기간 겹침은 휴관일·회차·잔여석 확인이 아니라는 안내를 날짜 입력과 추천 결과에 둔다.
- 로딩·정상 0건·통신 실패·계약 검증 실패·추가 로딩 실패를 구분하고 입력·이미 받은 페이지를 보존한다. 결과가 없다고 조건을 자동 해제하지 않는다.
- 결과 위에는 적용한 대상·상태·정렬과 방문·분위기·필수/선호 조건의 이름·값을 표시한다. 수정 중인 입력을 이미 적용된 조건처럼 표시하지 않는다.
- 출처 소유자·마지막 확인 시각·현재/예정/종료/취소·최신성 상태를 표시한다. 기관 결과는 실제 기관명·지역·검색 가능한 전시 수만 표시하며 기관별 필터는 제공하지 않는다.
- `INLINE`이면서 안전한 HTTP(S) 미디어 URL일 때만 이미지를 요청한다. `HIDDEN`·`LINK_ONLY` 및 이미지 로드 실패는 텍스트형 카드로 표시한다. 공식·미디어 출처 링크도 HTTP(S) 형식을 검증한다.
- OpenAPI 1.1의 API 동작을 유지하고 `openapi-typescript`로 타입을 생성하며 `openapi-fetch`의 생성 타입 기반 클라이언트를 사용한다. 관람시간 `anyOf`의 required-only 분기가 생성기에서 `unknown`으로 풀리는 문제는 양쪽 분기에 완전한 동등 스키마를 명시하는 1.1.1 호환 보정으로 해결한다. Zod가 모든 응답을 검증한 뒤 UI 모델로 변환한다. 생성 파일의 재현성 검사 명령을 제공한다.
- 로컬 Vite `/api` 프록시만 사용하고 CORS 전체 허용·외부 공개·인증 기능을 추가하지 않는다. 로컬 Django 설정은 loopback 호스트만 허용하고 요청 접근 로그를 출력하지 않는다.
- Vite의 내부 API 프록시 오류에서도 query 부분을 `[redacted]`로 치환한다. 입력 form의 자동완성은 끈다. 브라우저 자체 개발자 도구·기록 정책은 앱의 제어 범위가 아니다.
- 키 없는 데모는 임시 SQLite에 명시적 가상 전시·기관·근거를 적재하고 **실제 Django 검색·추천 서비스**를 호출한다. 기존 DB를 수정하지 않으며 프론트에 가상 데이터임을 표시하고 가상 공식 링크 이동은 제공하지 않는다. 데모를 별도의 추천 알고리즘으로 구현하지 않는다.

## 제외 범위

실제 취향 테스트/프로필 계산·홈 추천 6건과 전시 소식·관심/최근 본 저장·비교·상세 API/화면·작품/작가·지도/위치·운영시간/휴관일·실제 Source 특성 백필·staff UI·외부 배포는 포함하지 않는다. OD-004의 최종 로고/폰트는 확정하지 않고 시스템 Serif/Sans 대체 서체를 사용한다.

## 레퍼런스와 시각 방향

[OlfIt](https://github.com/Joraemon-s-Secret-Gadgets/olfit) 검토일은 2026-09-03이다. 에디토리얼 여백, 얇은 선, 입력과 추천 근거의 근접 배치만 참고한다. 로고·사진·코드·문구·정확한 배색·히어로 구도는 복제하지 않는다. 현재 화면 토큰은 웜 아이보리 `#F2F0E9`, 표면 `#FAF8F2`, 먹색 `#252923`, 회색 `#6F716B`, 선 `#D6D3C9`, 저채도 청회색 `#66777A`를 사용하고 한국어 Serif 제목·Sans UI를 유지한다. 도록의 페이지 번호와 수평 구분선을 활용한 텍스트 전시 카드를 기본으로 한다.

[Houston Group](https://houstongroup.com.au/)은 2026-09-04에 고정 헤더, 첫 화면을 채우는 미디어, 큰 선언문과 풀폭 콘텐츠가 이어지는 에디토리얼 리듬만 참고했다. 검정 중심 배색·서체·이미지 색감·문구·세부 인터랙션은 복제하지 않는다. 미감 홈은 웜 아이보리·먹색·석회색·흐린 청회색·옅은 흙색과 자연광을 사용하고, 원색·네온·광고 캠페인 같은 과장된 채도를 피한다.

홈 필름은 2~4%의 느린 패닝·확대와 부드러운 디졸브만 사용한다. 그 밖의 모션은 CSS로 구현하며 페이지·상태 전환은 180~240ms, 장식 섹션 등장은 280~400ms와 8~12px 이내 이동으로 제한한다. CTA, 필수조건, 확인 필요 정보에는 등장 지연을 적용하지 않는다. `prefers-reduced-motion`에서는 video 요소와 모든 비필수 움직임을 제거한다.

## 개인정보와 실패 경계

- 검색어·조건·추천 payload는 현재 탭의 메모리에만 둔다. URL query/history state·localStorage·sessionStorage·쿠키·로그·분석·장기 프로필에 복제하지 않는다. 비민감한 고정 탭 식별자 `/discover#recommend`만 예외로 허용하며 GET 검색의 HTTP 요청 query 자체는 TP-004 계약을 따른다.
- TanStack Query의 비활성 캐시 수명은 0, 자동 재시도·포커스 재요청은 끈다. Zustand persist와 Query Devtools/캐시 persistence, 이벤트 SDK를 추가하지 않는다.
- API 호출은 `credentials: omit`, `cache: no-store`, referrer 최소화와 취소 신호를 사용한다. 예상치 못한 응답은 안전한 한국어 오류로 처리하고 서버 예외·원문 payload를 출력하지 않는다.
- 외부 스크립트·웹폰트·API 키·분석 서비스는 필요 없다. 공식 이미지·링크는 검증된 권리와 URL 정책에 따른 명시적 예외다.

## 검증과 완료 기준

1. 생성 타입 재현성, TypeScript 검사, 프로덕션 빌드가 통과한다.
2. 경계 테스트는 enum·출처·날짜·URL·미디어 권리·주요 추천 lifecycle·별도 확인 후보·계약 오류를 검증한다.
3. 요청/상태 테스트는 무료 예산 0, 날짜/시간 범위 오류, 필수·선호 구분, 분위기 최대 3개, 적용 전 draft 보존, 탭 복귀, 페이지 초기화, 늦은 응답/추가 실패를 검증한다.
4. 실제 컴포넌트 테스트는 `/`와 `/discover`의 분리, 경로별 단일 `main`·`h1`, 홈 API 0회, 실제 링크 목적지, 추천 fragment 초기화, 홈 필름 속성·poster·reduced-motion 대체, 검색→결과·더 보기, 추천→별도 확인 구역, 0건·오류·재시도, Radix 키보드/ESC/포커스 복귀, 이미지 권리·실패 대체와 외부 링크를 검증한다.
5. 데모 서버는 임시 DB에서 외부 키/네트워크 없이 가상 데이터를 생성하고 실제 검색·추천 API로 정상·필수조건·0건을 재현한다.
6. 화면 기본 텍스트 16px, 제어 라벨 14px 이상, 읽을 수 있는 focus, mobile 1열, 200% 확대 대응 CSS, reduced-motion 규칙을 둔다. 1440px·390px과 `/discover` 직접 진입을 확인하고 실제 스크린리더/브라우저 수동 검증의 미실행 항목은 최종 결과에 구분한다.
7. 기존 Django 검색·추천 API 회귀와 변경 문서 참조, `git diff --check`를 확인한다. 완료 전 실행 결과를 기록한다.

## 실행 증거 · 2026-09-03

구현과 자동 검증을 마쳤으며 실제 브라우저 수동 검수는 남아 있다. 외부 배포는 하지 않았다.

- Windows, Node.js 24.15.0, npm 11.12.1, Django 5.2.17에서 검증했다.
- `frontend`: 최종 `npm test`는 4개 파일·38개 테스트 통과. `npm run build`의 TypeScript 검사와 Vite 프로덕션 번들, `npm run api:check`, `npm run format:check` 통과.
- 설치 시 npm audit은 196개 패키지를 검사하고 알려진 취약점 0건을 보고했다. 검사 범위는 패키지의 알려진 취약점에 한정된다.
- `uv run --project backend python backend/manage.py test tests --verbosity 1`: 193개 통과, Django system check 문제 0건. 데모 보호·실제 API 테스트 2건을 포함한다.
- 실제 loopback Vite → Django → Zod 검사: 기본 검색 8건, 예산 0 추천은 주요 2건·확인 필요 1건. 실행기와 API는 외부 데이터 API·키 없이 동작했다.
- 기존 `backend/db.sqlite3`의 크기 2,043,904 bytes, UTC 수정 시각 `2026-08-30 12:35:04`가 실행 전후 동일함을 확인했다.
- 변경 Markdown의 로컬 링크 존재 여부와 `git diff --check`를 확인했다. 생성 OpenAPI 타입은 정본과 일치한다.
- 미실행 검증: 실제 스크린샷·DOM/브라우저 E2E·모바일 실기기·200% 확대·스크린리더 확인. 전체 P0 접근성·사용성 검수와 공개 운영 준비는 아직 완료되지 않았다.

## 에디토리얼 화면 확장 실행 증거 · 2026-09-04

## 몰입형 홈·탐색 경로 분리 실행 증거 · 2026-09-04

외부 배포 없이 `/`를 로컬 장식 미디어만 사용하는 브랜드 홈으로 재구성하고, 검색·추천은 `/discover`로 분리했다. 검색·추천 API와 정본 데이터 계약은 변경하지 않았다.

- `frontend`: 최종 `npm test`는 4개 파일·48개 테스트 통과. 홈 API 0회, 경로별 단일 `main`·`h1`, 고정 추천 fragment, 같은 fragment에서 헤더 링크 재선택, film 속성·모바일/reduced-motion poster 대체, 세 시각 챕터, 기존 검색·추천·오류·권리 대체 회귀를 포함한다.
