# TP-010 로컬 마무리

## 승인과 완료 기준

2026-09-07 사용자가 공개 배포 없이 로컬에서 동작하는 프로젝트로 마무리하겠다고 결정하고 CI 브라우저 회귀와 운영 준비의 로컬 범위 진행을 승인했다. 호스팅·도메인·HTTPS·유료 서비스·공개 배포·운영자 계정 생성은 이번 완료 조건에서 제외한다. main의 기존 TP-009 변경을 보존한다. 새 승인·커밋·푸시를 자동으로 만들지 않는다.

## 실행 범위

1. Playwright로 홈의 API 비호출, 둘러보기·검색·전시 기간 추천·상세·관심 저장과 비교·공식 안내 경계를 실제 Django API에 연결해 반복 검증한다. 임시 가상 DB와 새 브라우저 컨텍스트를 사용하고 실제 사용자 저장소를 사용하지 않는다. 외부 사이트 접속은 차단하며 공식 링크 계약은 네트워크에 의존하지 않는 명시적 응답 fixture로 검증한다. 데스크톱 Chromium과 390px, Firefox·WebKit 프로젝트를 준비해 가용 환경에서 실행한다.
2. 같은 테스트를 로컬 명령과 GitHub Actions에서 실행하도록 구성한다. 이 작업은 테스트 설정이며 서비스 배포가 아니다. CI는 잠금 파일을 사용하고 실제 DB·비밀값·개인 입력을 읽거나 업로드하지 않는다. 원격 실행은 실제 push 후의 별도 증거로 구분한다.
3. 실제 데이터 모드의 loopback 단일 origin 로컬 실행 명령을 제공한다. 가상 데이터를 실DB에 적재하지 않으며 미적용 migration은 명시적인 백업·준비 절차로 안내한다. health·직접 경로 새로고침·종료와 파일 보존을 검증한다. 정적 빌드는 임시 디렉터리에 만들고 상속된 키·프론트 환경 파일을 사용하지 않는다.
4. 백업을 원본과 다른 새 DB 파일로만 복원하는 명령을 제공하고 무결성·기존 파일 덮어쓰기 거부·복원 DB 기동을 검증한다. 실제 DB를 교체하거나 손상시키지 않는다. 실행·정지·백업·복원·문제 해결 절차와 가상/실제 모드·브라우저 저장소 차이를 문서화한다.

기존 네이티브 실행을 기준으로 하며 Docker 설치·컨테이너·공개 운영 완성을 요구하지 않는다. 실제 작품 Source, 관람 정보 전체 확보와 포괄 P0 적응형 취향 등은 이번 로컬 완료 범위에 추가하지 않는다.

## 소유와 검증

- 루트: 문서·프론트 테스트 의존성/설정·Playwright E2E·CI·전체 통합 검증.
- 독립 에이전트 1명: Python 로컬 실행기·복구 도구와 직접 관련 테스트. 재위임과 공유 파일의 동시 수정은 금지한다.
- 검증: 새 실행·복구 경계의 실패 테스트 후 구현, 전체 backend tests와 frontend tests·타입·빌드·계약·형식, 네이티브 smoke와 브라우저 회귀, 변경 문서 참조와 diff 검사. 각 명령은 의미 있는 변경 뒤 한 번 실행하고 실패·새 변경이 있을 때만 다시 실행한다.
