# TP-007 실데이터 연결과 공식 관람 근거

## 목적과 승인 근거

2026-09-06 잔여 작업 검토에서 제안한 첫 작업인 기존 실데이터의 최신 DB·검색·추천 연결과 공식 관람정보·휴관일 보강에 대한 사용자의 "작업 바로 진행해줘" 승인을 기록한다. 기존 TP-001~006의 게이트·출처·권리·개인정보 원칙을 유지한다. 전체 P0 구현이나 공개 배포 승인을 뜻하지 않는다.

## 범위와 계약

- 기존 SQLite는 SQLite backup으로 보존하고 migration·registry 초기화·시간 경과 상태 재계산·검색 파생본 재구축을 수행한다. 기존 ID·SourceRecord·감사 이력·마지막 공식 확인 시각을 임의로 바꾸지 않는다. 오프라인 백필은 재확인 성공으로 세지 않는다.
- 실제 재확인은 공통 refresh 서비스를 이용한다. 문화정보 API는 대상 원본 ID의 상세만 순차 조회한다. 서울 CSV는 명시적으로 제공한 공식 파일을 사용하며 관측·획득 시각을 보존한다. 오래된 자격 심사 fixture를 운영 재확인 기본값으로 사용하지 않는다. 외부 오류는 마지막 정상 정본을 보존하고 기존 실패·health 규칙을 따른다.
- 선택 필드 확장은 공식 제공 범위를 확인한 문화정보 API `price`, 서울시립미술관 CSV의 `관람료(원)`, `전시(관람)시간`, `전시부문`에 한정한다. 누락한 선택 열은 핵심 품질 실패가 아니다. 나머지 예약·접근성·감각·관람시간 정보는 공식 근거가 없으면 `UNKNOWN`이다. 이미지·좌표·장문 설명 수집은 확장하지 않는다.
- 가격은 명백한 무료 또는 식별 가능한 성인 기본권만 정규화한다. 할인·연령별 혼합·불명확 범위의 최저가를 기본권으로 만들지 않는다. 매체는 공식 전시부문에 명시된 승인 코드만 사용하며 제목·작가·기관명으로 분위기나 안전정보를 추정하지 않는다.
- 선택 정보와 feature 백필은 현재 채택된 SourceRecord를 근거로 하며 원본·규칙 버전·확인 시각을 추적한다. 반복 실행은 같은 근거를 중복 누적하지 않는다. 원본 변경 시 이전 근거는 현재값에 영향을 주지 않아야 한다.
- `OperatingSchedule`은 전시 또는 기관과 SourceRecord를 연결하고 적용 시작·종료일, 요일별 개관시간, 확인된 휴관·임시 변경을 구분한다. 시간·요일·대상 기관·기간을 검증한다. 개관 여부가 명확하지 않은 원문은 `UNKNOWN`으로 보존한다.
- 날짜를 지정한 추천은 전시 기간 안에 공식 일정상 개관이 확인된 날이 최소 하루 있어야 한다. 확인된 임시 변경을 정기 일정에 우선하며 동순위 충돌·일정 미확인은 통과시키지 않는다. 날짜를 지정하지 않은 탐색 추천은 현재 계약을 유지한다. 실제 가능한 날짜 근거를 사용자에게 전달하고 잔여석·예약 가능 여부를 보장하지 않는다.
- 데이터 파이프라인은 `backend/data_pipeline/`, 정본·운영일 판정·추천 API는 `backend/apps/`가 소유한다. API 응답 확장은 OpenAPI → 생성 TypeScript → Zod → UI 순으로 맞춘다. 화면은 기존 Radix 직접 사용을 유지한다.

## 개인정보와 외부 의존성

일반 계정·서버 프로필·검색 입력 저장·외부 행동 분석을 추가하지 않는다. API 키는 기존 환경 파일에서 읽되 출력·이력에 남기지 않는다. 승인 Source의 공식 데이터 읽기만 수행하며 외부 게시·배포·메시지 전송은 하지 않는다. 데모와 자동 테스트는 외부 키 없이 수행한다. `PROVISIONAL`의 적격 레코드 서비스 가능 원칙을 유지한다.

## 구현 순서와 검증

1. 운영일 모델·판정과 실제 Source 입력/백필을 독립 구현한다. 실패 테스트로 UNKNOWN·휴관·충돌·출처 갱신·멱등성과 실패 시 정본 보존을 검증한다.
2. 실제 재확인 명령을 연결하고 누락 입력·차단 기관은 네트워크 전에 거부한다. 과거 fixture와 실제 재확인 모드를 분리한다.
3. 백업 후 기존 DB를 업그레이드하고 실제 공식 재확인·검색·추천 응답을 점검한다. 외부 접근 실패가 있으면 성공으로 기록하지 않는다.
4. Django 회귀·migration 일치, 변경된 API의 생성 타입/Zod·프론트 테스트·빌드, 로컬 브라우저 연결과 `git diff --check`를 확인한다.

## 완료 기준과 제외

기존 데이터를 보존한 최신 DB에서 실제 검색·추천 API가 동작하고, 승인 선택 필드가 근거를 갖고 정본과 추천에 반영되며, 날짜 추천에서 휴관·미확인을 개관으로 처리하지 않아야 한다. 출처별 확보량과 미확인 항목을 실행 증거에 기록한다. 상세·관심·취향 테스트·비교·지도·작품·Admin·공개 스케줄러·배포는 후속 작업이다.

## 2026-09-06 실행 증거

구현·오프라인 회귀·로컬 연결 검증을 수행했다. 외부 재확인과 실제 관람정보 확보는 아래 제한이 남아 있다.

- 최초 백업: `data/incoming/backups/db-20260906T104543Z-78561d23.sqlite3`. 가격 규칙 버전 추가 전에도 `db-20260906T105902Z-faf2a5fb.sqlite3` 백업을 만들었다. 두 백업 모두 SQLite 무결성을 확인했다. 최신 catalog migration은 `0006_priceoption_rule_version`이다.
- 원본 백업과 최종 DB를 비교해 기존 전시 318건·SourceRecord 493건·수집 실행 3건의 ID 소실 0, 기존 원본 payload·content hash 변경 0을 확인했다. 최종 SourceRecord는 497건이며 기존 전시 ID는 모두 유지했다. 공식 확인 시각이 달라진 전시는 실제 재확인에 성공한 ID `1, 6, 7, 11`뿐이다.
- 서울 열린데이터광장 공식 CSV를 2026-09-06 19:47 KST에 새로 받았다. 파일과 SHA-256·취득 시각·dataset URL을 `data/incoming/2026-09-06/{sejong,sema}.csv` 및 각각의 `.provenance.json`에 보존했다. 파일의 allowlist 원본은 세종 441건, 서울시립미술관 28건이다. 재확인 대상은 세종 현재 전시 1건·시립미술관 현재 전시 3건이며 run 4·5가 모두 성공했다.
- 문화정보 API는 run 6에서 응답 시간 초과로 실패했다. 별도 상세 1건의 읽기 진단에서도 `URLError → TimeoutError`를 확인했으며 인증 키·원문 URL을 출력하지 않았다. 수원시립미술관 2건·국립민속박물관 1건은 이전 정상 정보와 `STALE` 상태를 유지했다. 실패를 성공·승격 근거로 바꾸지 않았다.
- 현재·예정 검색 결과는 7건이고 기본 추천 UI는 요청 limit에 따라 6건이다. 현재 추천 특성 snapshot에는 명시적 매체 5종의 근거 assertion 7건이 있다. 승인된 좁은 가격·일정 파서로 확정할 수 있는 현재 전시의 가격과 운영일은 각각 0/7건이다. 미확인을 무료·개관으로 채우지 않았으며 `2026-09-07~08` 날짜 추천은 0건이고 입력 조건은 유지됐다.
- 휴관일·임시 개관·동순위 충돌·교체된 근거·긴 기간 경계, 가격 혼합 문구, 기존 특성 보존, 반복 백필·원본 불변 재확인, 생명주기 날짜 경과, fixture 기본값 제거, 백업 후 원본 보존을 자동 검증했다. Django 226개 테스트 통과, `makemigrations --check --dry-run` 변경 없음. 프론트 63개 테스트·production build·OpenAPI 생성 타입 일치·Prettier 검사 통과, `git diff --check` 통과.
- 로컬 실제 DB의 검색·기본 추천·날짜 0건 경로를 브라우저로 확인했다. 키 없는 격리 데모에서는 월요일 9/7 휴관을 건너뛴 9/8 10:00~18:00 표시를 확인했다. 390px 화면에서 새 날짜 안내를 시각 확인했고 문서 가로 폭은 390px로 넘침이 없었다. 전체 자동 브라우저 E2E·실기기·스크린리더 검수 완료를 뜻하지 않는다.

남은 연결 작업은 문화정보 API 정상 응답 후 3건 재확인과, 현재 CSV에서 비어 있는 가격·운영일을 보완할 공식 근거 확보다. 새 HTML 출처나 기관별 일정 수집기는 Source Registry·권리·정규화 규칙을 먼저 확정해 추가해야 한다. 상세·관심·취향 테스트 등 후속 제품 기능은 이 패킷으로 완료 처리하지 않는다.
